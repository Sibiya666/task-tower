# Выполнение первого этапа Task Tower

План: [pilot readiness](../superpowers/plans/2026-11-01-pilot-readiness.md).

## Решения реализации

- Повторно использована отдельная чистая рабочая копия task-tower в feature-ветке. Исходная башня и рабочая копия Dialoid не изменяются. Дополнительный worktree для разработки этого инструмента не создавался.
- Python 3.11+ со стандартной библиотекой: установленный bundled runtime позволяет начать без установки пакетов.
- Аудит проверяет только доступность tools; команды probes запускаются исключительно с `--run-checks`. Это устраняет возможность незаметного исполнения манифеста при чтении состояния.
- Windows: вместо taskkill применяется Job Object с запуском приостановленного процесса, назначением в job до ResumeThread и kill-on-close. Стоимость решения — отдельный Windows-модуль, зато охвачен ранний выход родителя.
- Внешний путь отчёта обязателен: проверка не загрязняет целевой репозиторий и не перезаписывает его документы. Сырые потоки команд временные, в JSON только хеши/размеры; этот отчёт среды не подменяет будущие доказательства приёмки задач.

## Независимая приёмка

Агент тестовой приёмки независимо прогнал 25/25 тестов на Windows и проверил CLI на своей временной Git-копии: аудит не исполняет манифест, baseline требует явного запуска, dirty блокирует команды, night_ready остаётся false.

Агент code review нашёл Important-дефект: внешний путь отчёта мог быть hardlink на документ проекта, и обычная запись перезаписывала оригинал. Регрессионный тест воспроизвёл проблему (RED); запись заменена на временный файл с атомарной заменой записи каталога (GREEN: итоговый набор 26/26 PASS).

Отложенное Minor-замечание: нереалистично большой конечный timeout вроде 1e308 может дать OverflowError при переводе в миллисекунды Windows. Пример проекта использует 600 секунд. Перед расширением формата ограничить поддерживаемый диапазон; пока не задавать такие значения.

Полная архитектура, очередь, агентный runtime adapter и ночной автомерж этим этапом не реализованы.
