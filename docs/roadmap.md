# Development roadmap

Backlog structure: large features are parent Issues with native sub-issues; milestones represent implementation stages or releases. These are independent relationships: a feature can span stages. The bookshelf projects them into the Tasks book, while Ideas retains proposals and the Project library links their Markdown artifacts. See [bookshelf hierarchy and current limits](github-books.md#target-bookshelf-hierarchy). Issue #13 is the overarching autonomous-development initiative; its existing child work remains traceable rather than being recreated. Issues #22/#23 must preserve native hierarchy and stage membership in the books.

The native development epic is [Issue 13](https://github.com/Sibiya666/task-tower/issues/13). Issues are the task source; this page records ordering and capability boundaries. The existing independent PR acceptor and the current chat's manual orchestration do not constitute a background development executor or automatic PR intake service.

[24 — project onboarding](https://github.com/Sibiya666/task-tower/issues/24), [14 — dispatcher](https://github.com/Sibiya666/task-tower/issues/14), [22 — session capture](https://github.com/Sibiya666/task-tower/issues/22) and [15 — executor](https://github.com/Sibiya666/task-tower/issues/15) passed exact-main acceptance and automatic closure. Current parallel work is [16 — independent stage pipeline](https://github.com/Sibiya666/task-tower/issues/16) and [23 — overlay books](https://github.com/Sibiya666/task-tower/issues/23), with separate worktrees and independent acceptance. Follow [continuous parallel process](development-process.md): refill up to two authorized independent Issues without a prompt, but serialize integration. Active-chat coordination is not a persistent execution pool.

The following implementation stages use native GitHub milestones: [MVP](https://github.com/Sibiya666/task-tower/milestone/1), [Night pilot](https://github.com/Sibiya666/task-tower/milestone/2), and [Harness and interface](https://github.com/Sibiya666/task-tower/milestone/3). Implemented foundations include the Codex observer overlay, readiness audit, interactive harness bootstrap, private connections/CLI and HTML books, and postmerge acceptance/publication paths. Project-first onboarding is accepted; a code path is not evidence of deployed runners, a continuously running synchronizer, or night readiness. The accepted foreground dispatcher and development executor are documented in [dispatcher operations](dispatcher.md) and [executor operations](executor.md). Independent stages (#16) are under implementation; automatic PR handling (#17) and daemon orchestration remain planned.

The architecture's target design remains in [the architecture spec](superpowers/specs/2026-11-01-agent-development-architecture-design.md); current onboarding requirements are in [the accepted spec](superpowers/specs/2026-11-01-project-onboarding-design.md). Native Issue dependencies, Project membership/status and milestones must be reconciled without replacing historical descriptions or acceptance evidence.

Accepted session capture and provenance-only legacy migration are documented in [capture operations](session-capture.md). Native relationships are exposed in structured data. The current #23 branch adds the hierarchical overlay dialog, bounded progressive refresh and immutable artifact declarations; native, full-diff and exact-main acceptance remain separate required gates. Existing host authentication reaches the dispatcher proof source without granting credentials to model processes or changing completion proof requirements.

The executor provides local durable admission, bounded isolated foreground attempts, cancellation and fenced recovery. A validated execution result never closes an Issue. Real installed Codex scratch execution is recorded separately from fixture transport tests; persistent automatic refill and stage/merge orchestration remain #16/#18/#19 and #17.
