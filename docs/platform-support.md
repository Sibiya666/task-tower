# Поддержка платформ и границы версии

Решение пользователя от 2026-11-02: текущую версию доводим для Windows; нативную работу, которую Windows не проверяет, переносим в следующую версию. Это ограничение области релиза, а не доказательство готовности Linux/macOS.

| Часть | Текущая версия | Linux/macOS |
| --- | --- | --- |
| Базовый CLI, чтение GitHub, схемы, парсеры, политики | Существующие переносимые контракты сохраняются | Применимые регрессии остаются в CI |
| Существующий foreground Codex/custom executor | Существующий контракт сохраняется | Эта поправка его глобально не отключает |
| Pipeline work/watch и внутренние helpers | Нативная приёмка Windows; до завершения приёмки релиз не готов | Запуск явно недоступен до побочных эффектов; #59/#60 |
| Pipeline adapter/status/cancel/reconcile --inspect | Переносимые чтение/управление и защита от replay | Сохраняются; cancel не доказывает очистку |
| Новые группы и датчики ёмкости #18 | Политика переносима; нативное исполнение и пилот квалифицируются на Windows | Нативные датчики/группы — #61 |
| Новый OpenCode/custom протокол #21 | Нативная квалификация Windows ещё обязательна; CLI/политика могут быть блокерами | Нативная квалификация — #62 |
| Оверлей | Windows | Не заявлен переносимым |

Три платформы в CI сохраняются. Зелёная проверка переносимого кода не выдаётся за нативный пилот неподдерживаемой платформы. Исключаются только тесты фактически отложенного исполнения; чистые политики/протоколы, проверки отказа до запуска, существующие переносимые процессы и Windows-регрессии остаются обязательными.

Задачи находятся в Project этого репозитория как planned/Backlog, связаны нативной иерархией GitHub и не включены в текущую очередь исполнения. Книги агрегируют эти Issue/milestone/связи; отдельная копия бэклога в репозитории не становится источником истины.

POSIX-черновик сохранён в [отдельной ветке](https://github.com/Sibiya666/task-tower/tree/wip/vnext-posix-containment), коммит `18e9a3985ad3b86a02d58703ef8e8a2afdd9a0e2`. Это непринятый WIP с ручной диагностикой, а не готовая поддержка. Сохранены фактические ошибки и неизвестные исходы. Windows Job Objects и исправления SQLite остаются в текущей работе.

Для включения каждой новой платформы нужны Superpowers, независимые приёмщики спеки/разработки/теста, настоящие нативные доказательства, точная PR head/base-приёмка, актуальный CI, независимая проверка main и автоматическое подтверждённое закрытие Issue. Политика ресурсов не навязывает лимит2, но не расширяет бюджеты, полномочия, доступ к провайдерам или моделям. Ночная готовность пока не заявляется.
