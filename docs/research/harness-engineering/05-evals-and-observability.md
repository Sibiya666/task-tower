# Evals и наблюдаемость: принятый результат вместо зелёного счётчика

Дата анализа: 2026-11-06. Каноническая задача **tt-e4n.5**, родитель tt-e4n; [Issue55][issue55] — сохранённый контекст. Это исследовательский дизайн, **не исполненный eval harness**. Все новые случаи E1–E12, синтетические проверки, model runs и fault trials ниже имеют статус **NOT RUN**. Измеренных улучшений качества, стоимости или времени владельца нет.

Предлагается оценивать отдельно работу исполнителя, решения независимого приёмщика и enforcement контроллера. Общий зелёный процент скрывает, например, правильный отказ от опасной операции, отсутствие judge и принятие устаревшего SHA. Для каждого результата нужны заранее определённый oracle, полный знаменатель и связанная история попыток. Beads остаётся authority задач, зависимостей и истории; Books — read-only проекция. Manifest ниже не становится второй очередью или правом на effect.

## 2. Что golden-проверки действительно проверяют

В C2 `tests/README` называет L0 статикой, L1 проверкой ворот, L2 решением задач агентом и L3 сравнением с baseline; обычный suite описан как L0/L1 плюс контракт L2/L3. Shell `test_05_golden_tasks.sh` прямо исключает запуск модели. Он читает YAML, при наличии PyYAML разбирает синтаксис, затем проверяет поля/идентификаторы, число случаев и категорий, дату, наличие safety, непустые reject и текстовые признаки проверяемого accept. Он ищет записанные `pass_rate`, а не получает новые решения. `cmd:` внутри YAML сам по себе не исполняется golden shell-проверкой. Это пригодность описания к будущему опыту, не quality score. [C2][course-shell]

Python `test_golden_set_is_usable` также читает YAML: минимум восемь cases, уникальность ID, `runs_per_case >= 3`, обязательные непустые поля, минимум три категории/safety и хотя бы один записанный baseline ниже 0.95. Отсутствие golden-файла или PyYAML даёт skip. В этой функции нет запуска prompt, оценки artifacts или вызова модели; проверки даты и обязательного baseline у каждого case, имеющиеся в shell, в ней не эквивалентны. Поэтому общий ярлык «Python-версия» не доказывает одинаковую полноту двух реализаций. [Python:267–296][course-python]

Fixture `cases.yaml` содержит version/date/repeats/defaults, дословные prompts, accept/reject и baseline, включая safety/context/forensics. Его комментарий предлагает архивировать задачу после серии успехов, а shell считает весь набор с baseline ≥0.95 недостаточно различающим. **Adapt:** версии, критерии и adverse variants. **Reject для регрессионной политики:** удаление успешно решённых случаев ради низкого score. Решённый дефект остаётся regression; сложный discrimination set обновляется отдельно. И восемь случаев, и три/пять repeats, и 180 дней в курсе — параметры учебного контракта, не статистическое обоснование нашего размера, TTL или бюджета. [Fixture:9–31][course-cases], [shell][course-shell]

| Уровень нашей проверки — предложение | Требуемое свидетельство | Какого вывода недостаточно |
| --- | --- | --- |
| S: metadata | Case/rubric/schema/hash валидны, broken mutation обнаружена | «Агент решает задачу» из наличия accept в YAML |
| T: реальный tool rejection | Конкретный вызов ограниченного инструмента действительно отклонён, effects/readback проверены | «Контроллер защищает merge» из строки `agent_refuses` |
| M: model task evaluation | Независимый oracle оценивает фактический response/artifact и полную попытку | Самооценка исполнителя или его reviewer как собственная ground truth |
| I: effect-bound integration | Отказ/допуск на реальной разрешённой границе, source/owner/effect identity и readback | Успех parser или fake fixture как доказательство runtime enforcement |

Здесь выполнено только чтение источников и статическая проверка написанного документа. Даже S-проверки будущего набора не запускались. Для T/M/I нужны отдельные конкретные разрешённые fixtures, execution policy и независимая приёмка; этот отчёт их не предоставляет.

До будущего исполнения preparer создаёт case/version, inputs, mutation, rubric, expected decision и evidence key; независимый adjudicator проверяет их **до** результатов. Evaluated executor/reviewer получает разрешённую задачу и публичные acceptance criteria, но не скрытые answers/labels/held-out rubric. Автор candidate не утверждает его правильность; tested reviewer не метит свои решения как ground truth. Детерминированные условия проверяются отдельным oracle, содержательные — отдельным blinded adjudicator. Конфликт adjudicators сохраняется как `adjudication_pending`, с причинами и отдельным решением арбитра; до него нет доказанного correct/error. Одной смены имени процесса или модели недостаточно для независимости входов.

Для executor оценивается фактический ответ/артефакт по key. Для reviewer подаётся независимый balanced inventory acceptable/unacceptable packets, включая правильные отказы и ошибки, а не только выбранные успешные outputs executor. Для controller оценивается effect trace и state/readback. Такой разбор позволяет отличить плохой candidate, false accept reviewer и обход enforcement; общий end-to-end исход сохраняется дополнительно, без двойного счёта результата.

## 4. Splits, версии и сравнение

Предложение representative inventory начинается с **разрешённого** отбора реальных Windows/local workflow categories и сохранённых отказов: код, docs, source/CI evidence, handoff, безопасный отказ, recovery и координация. Оператор фиксирует окно отбора, доступные/исключённые задачи и причины, частоты/риски и веса strata до сравнения. Редкие опасные случаи можно oversample, но их challenge score публикуется отдельно от weighted routine score. Без census и весов это coverage register, а не оценка частоты production ошибок. Сейчас такого отбора/распределения нет.

| Набор | Назначение и правила |
| --- | --- |
| Development/calibration | Настройка инструкций, rubric и pilot дисперсии. Разрешён feedback; его результаты не confirmatory held-out evidence. |
| Held-out | Закрытые task families и labels; frozen inputs/rubric/selection/seed schedule до первого результата. Родственные mutation/повторные рассказы одного инцидента остаются в одном split. Просмотр ответа или настройка по нему переводит family в exposed/calibration, требует новой версии и нового held-out. |
| Regression | Сохранённые решённые cases с исходным expected behavior и историей. Исправление rubric создаёт новую версию с объяснением; старый результат не переписывается. Успех не удаляет case и не уменьшает знаменатель. |
| Discrimination/challenge | Отдельно versioned более трудные/новые случаи для различения candidates. Saturation мотивирует пополнение этого набора; не повод переименовать regression в бесполезный. Нельзя выбирать challenges после результата и выдавать их за frozen held-out. |

Hash inputs, family/split/rubric версии и exposure history обязательны. Public benchmark или ранее увиденный failure нельзя назвать чистым held-out без анализа загрязнения; происхождение training data модели обычно unknown. Неизменяемый model alias не гарантирует неизменяемую resolved version. Если её нельзя наблюдать, reproducibility ограничена, paired claim помечается соответственно. Хэш не скрывает answer от агента, которому доступны исходные bytes. Модель, hooks, libraries, network permissions и tooling frozen внутри сравнения; их изменение — новая condition. [H2 evaluation][h2-eval], [trust boundary][h2-trust]

Reuse H2 design: **B0** неизменённый harness; **BR** его повторы с тем же независимым selector; **H** ограниченный candidate. Baseline output должен быть допустимым победителем наряду с keep-original/reject-all. Основной contrast — одинаковый **полный** resource cap; равное число executor attempts — отдельный estimand, оно не уравнивает proposer/judge/review spend. При frozen library — независимые task-family clusters; при online learning — независимые streams, сохраняющие порядок и свои initial snapshots. Нельзя считать dependent repeats/stream tasks независимыми репликациями. Это сравнение **NOT RUN**, не внедрение H2. [Принятый протокол][h2-eval]

До отдельного будущего запуска оператор и независимый reviewer фиксируют выборку/repeats из доступного бюджета и pilot variance, meaningful effect из пользовательской ценности/риска, primary metric, caps и retry/stop policy. Значения сейчас не определены; определения метрик ниже уже определены. Остановка при policy/identity mismatch, утечке key, запрещённом effect или cap сохраняет первоначальные попытки. Unknown effect сначала reconcile. Нельзя добавлять retries до зелёного, менять threshold по held-out или компенсировать нарушение safety лучшим средним quality.

## 5. Словарь метрик и неопределённость

**Единицы.** Episode = заранее назначенная `task × repeat × arm`; attempt = конкретное исполнение/внутренний retry, связанный с episode; decision = verdict reviewer по одной versioned packet/pair. Один accepted result с одной identity считается один раз, даже если есть несколько receipts. Реальная поставка дополнительно требует exact-main/canonical gates: экспериментальный acceptance label их не заменяет. Весь planned inventory сохраняется, включая not_started/cancelled/failed/ungraded/unknown.

Для reviewer независимый oracle задаёт ground truth **acceptable/unacceptable packet**, не самооценку tested reviewer. Decision может быть accept/reject/escalate/unknown; последние два не переименовываются в reject. Acceptable safety response, содержащий правильный отказ от операции, — положительный результат соответствующей задачи. Для задач с ожидаемой эскалацией успех определяется rubric, а не частотой слова «нет».

| Метрика / единица | Числитель, знаменатель или интервал | Missing/zero и предел интерпретации |
| --- | --- | --- |
| Delivery / episode | Independently accepted unique results / **все planned episodes** arm | Unknown/ungraded не увеличивают numerator; это не доказанный quality failure. Planned=0 → undefined. Дополнительно planned→attempted→completed→selected→graded→accepted с причинами потерь, без survivor filtering. |
| Reviewer false accept | `FA = accepted unacceptable packets / все independently adjudicated unacceptable packets` | При denominator=0 undefined. Pending oracle вне adjudicated, но явно в общем inventory. Показывать raw counts и coverage, иначе always-abstain выглядит безопасным. |
| Reviewer false reject | `FR = rejected acceptable packets / все independently adjudicated acceptable packets` | При denominator=0 undefined. Correct refusal внутри acceptable response не false reject. Escalate/unknown отдельными cells для обоих ground-truth classes; не прятать их в correct. |
| Decision/adjudication coverage | Decisive accept+reject / все planned decisions; adjudicated / все planned decisions; дополнительно decisive among adjudicated | Все три знаменателя подписаны. Ошибка oracle не подменяется reviewer error. Наличие одного приемлемого примера не оценивает редкую FA. |
| Scored-only quality | Сумма frozen rubric scores / число graded episodes, отдельно по comparable rubric | Вместе с graded/planned и delivery. Missing judge не score=0; среднее только surviving grades не primary proof. Разные шкалы не усреднять как одну. |
| Accepted-result cost | **Весь observed spend arm**, включая failed/cancelled attempts, executor/proposer/selector/reviewer/oracle, retries/tools/CI и preparation, / unique accepted results arm | Accepted=0 → undefined при сохранённом общем spend. Missing spend → partial lower bound, не 0/полная цена. Publish coverage по компонентам и allocation shared costs заранее; без неё сравнение full cost недоступно. |
| Три cost ledgers | Money по фактической валюте/тарифной версии; compute/tokens/CPU отдельно; active owner minutes отдельно | Не суммировать минуты с деньгами без заранее принятой conversion. Cache/discount/free tier и unpriced CI отмечать; оценочная цена отдельно от billed. Owner/reviewer effort входит в соответствующий ledger, не исчезает как «бесплатное». |
| Owner effort и saving | Active intervention+review/recovery minutes по началу/концу nonoverlapping owner work intervals; saving = baseline effort − candidate effort на сопоставимой задаче/бюджете | Queue/waiting и elapsed latency отдельно. Без таймера/сопоставимого baseline — observed/partial effort, **не time saved**. Concurrent owner intervals считать union, не сумму перекрытий; отсутствующие intervals unknown. |
| Queue/service/end-to-end latency | Queue: eligible enqueue→actual start; service: start→attempt terminal; episode: authorized release→independent terminal acceptance/rejection/stop. Publish stage spans и отдельный actual-main delivery endpoint | UTC для cross-system ordering, monotonic для локальных durations; offset/precision и missing endpoint явны. Pending episodes right-censored в момент cutoff, rejected latency отдельно от accepted. Не считать первый token или execution_completed accepted endpoint. |
| Incident restoration / MTTR | Для заранее определённого incident: detection→подтверждённое восстановление требуемой способности; onset→detection отдельно, когда onset известен. Mean = сумма restoration durations / число restored incidents; также median/range и restored/all incidents | Невосстановленные incidents right-censored с elapsed at cutoff; restored-only mean явно условный, не общий MTTR. Missing detection → duration unknown. «Получено валидное evidence» и «устранена причина дефекта» — разные restoration contracts; последнее требует cause/fix evidence. |
| Regression | Ранее passing versioned cases, ставшие failing / все cases frozen regression inventory с previous pass; counts/severity и tested/eligible coverage отдельно | NOT RUN/missing — unknown, не pass. При denominator=0 undefined. Exclusion/смена fixture объясняется и версионируется, не убирается задним числом. Challenge score не заменяет этот показатель. |
| Повторные эффекты | Counts proposed, attempted, confirmed duplicates по stable effect identity; confirmed duplicates / все confirmed effects. Дополнительно episodes с duplicate / все planned episodes | Unknown remote outcomes отдельно, с reconciliation links. При нуле effects rate undefined; ноль effects в read-only опыте не доказывает идемпотентность runtime. Repeated intent и повторный фактический effect не одно событие. |

Полная confusion table хранит acceptable/unacceptable × accept/reject/escalate/unknown плюс unadjudicated, с source packet и verdict IDs. Частота выполнения отказов не достаточна: always-reject даёт большой FR, always-abstain низкие FA/FR при низкой coverage. Threshold приёмки замораживается до outputs, severity safety violations показывается отдельно; недопустимую операцию нельзя «окупить» более высокой средней delivery.

**Неопределённость.** Всегда публиковать counts, strata, follow-up cutoff, missingness и disagreement. Для fixed task families планировать paired differences B0/BR/H с повторениями внутри cluster; для online library — stream-level resampling, как в H2. Метод интервала, seeds, primary contrast и multiple-comparison rule фиксируются заранее. При малом числе независимых clusters показывать raw pairs/range и нестабильность; не изобретать confidence interval или significance из двенадцати названий. Отсутствие наблюдавшегося rare failure не доказывает нулевой риск. Для pending oracle можно отдельно показать best/worst bounds, не переименовывая их в измеренный score. **Данных для расчёта сейчас нет**, включая owner time, billed cost и latency распределения.

Антиметрики: throughput/закрытые cards без accepted outcomes; tokens/lines как качество; дешёвые неудачи при нуле accepted; easy-case pass rate с удалёнными regression; низкий MTTR после смены endpoint; «автономность» за счёт скрытого owner review; FA только среди удобных graded packets; отменённые/потерянные attempts вне цены. В каждой паре показывать accepted delivery вместе с coverage, полной ценой, severity и unchanged safety gates. Метрики курса полезны как вопросы; VCR, размеры golden и временные ориентиры не становятся универсальными policy. [C1][course-metrics]

## 6. Proposed manifest, trace и приватность

Это inspectable **схема предложения**, не сохранённый реальный run, parser или новая БД. Значения absent — `unknown` с причиной, не пустое «совпадение». Пример identity ниже синтетический; actual result всегда `not_run`. Ни private policy bytes, ни ответы скрытого oracle не подаются модели через этот manifest.

| Группа | Обязательные поля и смысл |
| --- | --- |
| Authority / hierarchy | `project_id`, repository, `bead_id`; legacy Issue — optional context URL; experiment/episode/case/family/arm/repeat IDs; `run_id`, `attempt_id`, parent/retry-of/reason. Claim/owner observation version/time отдельно от права launch. |
| Source | Exact source commit/tree; PR number и head/base pair; actual tested merge/source SHA; accepted main SHA и ordered parents, где применимо. API workflow head отдельно от checkout/artifact source. `not_applicable` отличается от `unknown`. |
| Inputs / environment | Task/input/schema/case/rubric/split hashes+versions, upstream pin, allowed artifact IDs, harness commit/config digest, policy identity/digest, model/provider **resolved** version либо unknown, sampling settings/seed и scope seed; runtime/tool/parser versions, initial library snapshot, network/effect policy and observed enforcement. |
| Actors / verdict | Executor, reviewer, oracle/adjudicator IDs/roles/process-context binding, independence statement и ограничения; packet/result digest, decision/ground-truth и adjudication status. Auth accounts/credentials в публичном binding не нужны. |
| Ordered trace | Event ID, per-run sequence, parent/span/causal links, stage, actor, UTC timestamp+precision, local monotonic start/end where available; planned→started→execution_completed→reviewed→accepted/done отдельными событиями. Не выводить причинность между машинами только из часов. |
| Effects / terminal | Intent/effect identity и type, allowed scope, attempted/confirmed/unknown, remote readback reference; cancel request/ack, cleanup requested/confirmed/unknown; terminal status/reason. Нет подтверждения cleanup — нет выдуманного stopped. |
| Costs / artifacts | Per-role attempts/cost/time coverage, caps и actual spend; оригинальный artifact hash/type/size/producer/source binding, restricted locator ID; отдельно redacted derivative hash, parent hash, transformation version и reviewer. Hash доказывает равенство bytes, не истинность содержимого. |
| Lifecycle | Public/restricted class, access owner, retention-policy version, review trigger/hold, deletion approval/evidence status. Unavailable/expired/quarantined/redacted — разные состояния с датой/причиной и сохранившимся identity, без подделки содержимого. |

Например: `experiment=proposal-v1, case=E11.v1, episode=E11.v1/B0/1, attempt=synthetic-a1, actual=not_run`. Это пример поля, а не якобы полученный результат. Trace только с `execution_completed` не подтверждает independent acceptance; bead closed не подтверждает runtime evidence. Read-only Books может показать partial history, но не восстанавливает отсутствующий attempt. [Handoff][handoff], [control][control]

**Field-level projection и retention — предложение, без изменения текущих записей:**

| Класс | Поля / доступ | Retention и недоступность |
| --- | --- | --- |
| Public redacted evidence | Public repo/bead/run/source identities, безопасные verdict/counts, sanitized errors, artifact provenance. Удалить secrets/authorization headers, env values, username/private absolute paths, raw prompts/chats и DB/config dumps; private resource names заменить scoped opaque IDs | Release evidence сохранять по принятой project evidence policy с versioned corrections. До её утверждения этот отчёт не задаёт срок удаления. Истечение upstream artifact явно `expired`; остаются ID/hash/сводка и предел воспроизводимости. |
| Restricted raw diagnostics | Только необходимый scoped raw log/artifact, input/key и original→redacted mapping; доступ авторизованному оператору и назначенному независимому acceptor по need-to-know. Evaluated agent не получает answer key | Раздельные retention classes: ordinary diagnostics до согласованного срока review/appeal; incident/effect-unknown — hold до reconciliation и разрешённого решения; скрытый key — до завершения/вывода split из обращения, затем restricted archive по policy. Конкретные дни определяет оператор по privacy/доказательствам/доступному storage до run. |
| Secrets / unnecessary private data | Tokens, credentials, полные DB, browser profiles и чужие чаты исключены из collection/model packet. Обнаруженный случай не публикуется; redaction отдельно проверяется | Incident response только в уже разрешённом scope; не копировать секрет для «доказательства», не удалять original history самовольно. Не проводить private scan ради полноты. |

Оператор — accountable data owner, независимый security/evidence reviewer проверяет release projection и решение о lifecycle; изменение обязательной retention/privacy policy или прав требует действующей user authority, не решения optimizer. Publication gate проверяет both public content и diff against intended projection, включая free-text errors/argv/attachments, а не только поле `token`. Нужные для acceptance поля после redaction должны остаться проверяемыми; иначе verdict limited/unverifiable. Hash частного пути/короткого секрета **не anonymization**, возможен перебор; для связи пользоваться opaque ID и restricted mapping. Удаление по будущей утверждённой policy оставляет tombstone/reason, не сочинённый PASS. **Сейчас нет collection/export raw data, deletion, новой retention настройки или изменения ACL.** [Trust audit][h2-trust]
