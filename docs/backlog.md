### Что именно требуется

`tt-ltz` сопоставляет реальные компоненты: задача/owner/dependencies/history Beads → артефакты Superpowers → работа и независимый review в Codex → настоящий PR/main/CI → read-only Books. Отчёт отделяет уже поставленный код, процедуру координатора и действительно отсутствующую связь, с точными ссылками на исходники. Если компоненты уже достаточны, нужно зафиксировать это, без придумывания новой реализации. Результат проходит независимую приёмку и обычные репозиторные gates.

Карта исходников и один ограниченный целевой результат: [Beads → Superpowers → Codex → GitHub → Books](beads-superpowers-codex-map.md). Наличие отчёта не заменяет его PR/main-приёмку или фактическую доставку `tt-x6t`.

`tt-x6t` использует принятую карту для одного ограниченного полезного результата в Books/overlay/integration. Сначала фиксируются исходные критерии, конкретный scope и разрешённые проверки. Применяются существующие компоненты; добавляется только подтверждённая недостающая связь. Приёмка включает реальные task identity/owner/state/history и свидетельства результата в Books, независимые PR head/base и exact-main проверки, настоящий CI и canonical close/readback. Статические проверки, WIP и одна административная правка бэклога не заменяют этот результат. Если необходимое наблюдение не разрешено или недоступно, карточка остаётся незавершённой с явным blocker.

Это две текущие карточки, не новый task engine и не постоянный граф ролей. Создание карточки не разрешает установку, hooks/setup, изменение model/account/auth/ACL/policy, новый native/model эксперимент, запуск старых workers или работу в другом репозитории. Необходимый конкретный шаг с недостающим разрешением сначала готовится для проверки и останавливается до эффекта. Старые B/G1/G2 не являются зависимостями этих карточек. Подробные исходные criteria хранятся в самих Beads, а не в копии исполняемой очереди Markdown.

## Границы первого релиза

Для текущей работы используется существующий Codex и канонический Beads через Superpowers. Books/overlay и CI сохраняют свои фактические возможности. Платформенные подробности прежних поставок и будущие карточки ниже не создают новую Windows-квалификацию, службу или другой task engine.

По явному решению пользователя известная нерешённая `tt-qrk.4` не блокирует первый релиз. Она остаётся открытой/blocked по отсутствию данных о причине и наблюдается отдельно; [условия и наблюдение](ci-known-issues.md). Это не разрешение принимать красный, отменённый или неполный CI, ослаблять assertions/timeouts либо обходить независимую PR/main-приёмку.

## Статусы и работа с очередью

Историческое наблюдение активации 2026-11-05: все 29 узлов ниже первоначально созданы `deferred`/без исполнителя; затем активированы восемь Windows-узлов и отдельно 14 исследовательских узлов — эпики `tt-bx1` / #44, `tt-e4n` / #45 и 12 детей. Остальные семь исходных будущих узлов остались `deferred`; прежнее «остальные 21 deferred» больше не действует. Это не свежий полный census/`ready` и не заявление о завершении исследований. В readback, закреплённом единой спецификацией, первые дети `tt-bx1.1` / #46 и `tt-e4n.1` / #51 ещё `in_progress` у исходного владельца; их claims не передаются этим документом. Исследовательская активация ограничена source analysis/предложениями, не даёт права upstream/model/native запусков, установки, ACL, новых сервисов или продуктовых изменений. GitHub Issues — внешние справочные карточки, не вторая исполняемая очередь; отменённые #17/#18 не становятся действующими зависимостями. Перед мутациями нужны свежие show/ready, зависимости и владельцы.

Для будущей активации нужен согласованный владельцем объём этапа; до реализации требуется независимо принятая Superpowers-спецификация. В разрешённом этапе карточка снимается с defer в настроенном Beads-проекте, проверяются зависимости и она захватывается одним исполнителем. Зависимость-ready не отменяет deferred или границы авторизации. Embedded-режим по-прежнему допускает одного писателя; распределённая блокировка не заявляется.

Каждая реализация проходит независимые приёмки спеки, разработки и тестов, свежую whole-diff PR-приёмку точных head/base, настоящий `task-tower/pr-acceptance`, все применимые CI, expected-head merge и независимую exact-main приёмку с подлинными артефактами. Слияния сериализуются. Для docs-only работает отдельно принятый typed route с `runtime_tests:not_run`; skipped runtime не превращается в runtime pass. Завершение в каноническом Beads сейчас выполняет координатор после фактических gates и проверяет запись истории; это не встроенный product-autoclose.
