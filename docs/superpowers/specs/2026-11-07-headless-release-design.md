# Минимальный релиз Task Tower без UI

Дата: 2026-11-07. Основание: согласованный в чате объём; пользователь поручил зафиксировать его и подготовить план. Документ не утверждает, что сервис уже работает.

## Цель и приёмка
Одна реальная задача проходит согласование → Beads → claim → worktree → Codex → независимый review → защищённый merge → проверку main → close/readback без ручной передачи между этапами. Пользователь согласует план, но не подтверждает каждый merge. UI исключён из разработки и приёмки.

## Выбранный подход
Один оркестратор в Linux Docker, Beads/Dolt — единственная система задач. Внешний фоновый коннектор запускает свой Codex app-server на машине с репозиториями. Менеджер на первом этапе — текущий чат: подготовка и согласование плана, разбор исключений. Отдельный менеджер-демон не нужен для первого запуска.

Рассмотрены: API с локальным журналом (выбран пользователем), Redis Streams (отложен), несколько оркестраторов (отложены). Предложение реализации: Python 3.11+, стандартная библиотека, SQLite только для журнала попыток/команд, HTTP JSON с ограниченным опросом. SSE не нужен без UI; сигнал о работе — версия готовности в ответе опроса, а не обязательная доставляемая очередь. Beads ready всегда определяет фактическую готовность.

## Контракт релиза
- max_active_tasks=2 на коннектор, настраивается; уменьшение не прерывает работу.
- Один worktree/ветка на задачу; проверка в отдельном контексте и checkout фиксированного SHA.
- Первичная проверка плюс максимум 3 цикла исправления/повторной проверки; затем needs_input.
- Задача занимает слот во время исполнения, review и merge. needs_input освобождает слот только после подтверждённой остановки всей её активности. Другие ready-задачи продолжаются.
- Потеря связи с оркестратором: текущая работа продолжается, новые задачи не принимаются, события сохраняются у коннектора. Неизвестная судьба работы не освобождает владение.
- Исполнитель уточняет внутренние шаги; новые исполняемые задачи/зависимости/изменения объёма требуют согласования через менеджера.
- Слияния сериализованы по репозиторию; новые head/base требуют новой проверки. Автоматический merge только после текущих обязательных CI и независимого одобрения. Закрытие только после exact-main проверки.
- UI, Redis, автоматическое распределение по нескольким машинам, сложная очередь возобновления, автоматическое восстановление неизвестных эффектов и отдельный агент-планировщик вне релиза.

## Минимальная надёжность
Один процесс-владелец оркестратора и один экземпляр каждого connector_id. Постоянные журналы в Docker volume и на хосте. Уникальный активный attempt на (project, bead). Beads не дублируется в SQLite.
Перед claim записать намерение, затем native claim/readback; при конфликте не запускать. Перед turn/start создать пустой thread и надёжно сохранить thread_id. Перед внешним эффектом сохранить command_id и фазу; повтор command_id возвращает прежний результат. При неоднозначном turn/start, merge или close после перезапуска — needs_reconciliation, без автоматического повтора. Известные недоставленные события можно дослать идемпотентно. Автоматическое продолжение прерванного исполнения отложено.
JSON-RPC id не считается ключом идемпотентности Codex. Не обещаем exactly-once внешних действий. thread/read/resume и список turns проверяются на установленной версии, восстановление истории не означает продолжение живого процесса.

## Данные и границы
Beads: задачи/приоритеты/граф/владение. Журнал: attempt_id, project_id, bead_id, phase, connector_id, thread_id/turn_id, branch/worktree, command_id, исходы, review SHA, PR/main SHA, correction_count, decision_id. Локальный журнал коннектора: inbox команд и outbox событий. Входящие события дедуплицируются по event_id, состояние обновляется одной транзакцией с фиксацией события.
Оркестратор не принимает произвольные shell-команды и файловые пути по API. project_id сопоставляется с доверенным конфигом хоста. Коннектор обращается исходящим соединением; API первой версии опубликован только на loopback хоста, с секретом из приватного файла и привязкой connector_id. Без внешней сетевой публикации.
Codex сохраняет действующую авторизацию, модель и ограничения среды. GitHub credentials не передаются модельным процессам; публикация/статус/merge через фиксированный доверенный helper. Ответы проверяющего валидируются и связаны с полным diff и точными head/base; слова approve сами по себе не разрешают merge.

## Перенос Beads
Первый smoke — новая изолированная тестовая база и только явно созданная пилотная карточка. Не импортировать автоматически старый backlog. Перенос канонической базы отдельным контролируемым шагом: остановить записи источника, native backup/restore, проверить identity/tasks/deps/history, переключить ровно одного писателя, исходник оставить неактивным. Нельзя монтировать одну embedded БД одновременно в хостовый bd и контейнер.
