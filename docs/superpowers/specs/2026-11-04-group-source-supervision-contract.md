# Actual group worker source supervision

Status: proposed correction/implementation detail for Issue18 initial preparation. This does not reduce the accepted60-second original registration/source budget or authorize claims before their coupled consumers exist. Original development rejection cf990bf9 remains open until real supervisor integration and fault tests pass.

## Actual process boundary

The installed parent starts one fixed trusted group worker child through existing platform process containment: Windows kill-on-close Job and POSIX session/group. The child retains its actual PID, actual RegistrationContext, loaded current pipeline/runtime and actual source/resource collectors. It owns every actual claim/intent/role in that worker lifetime. The parent never imports a serialized graph/observation/admission as authority, never performs a claim, and never acknowledges a child-owned action. Worker exit/lost control does not transfer original owners or release unknown fences. This remains single-installation/local ownership, not distributed Issue19.

The complete synchronous collection, including actual credential lookup, HTTP/DNS/redirect/response reads and local Git, runs inside this contained child. Before opening a registration context the child emits a source phase start with its freshly allocated host phase UUID. The parent starts an original monotonic60-second ceiling for that phase immediately upon observation, additionally capped by an existing task deadline when the worker already has one. Child RegistrationContext still independently enforces its original deadline; parent termination is a hard outer ceiling, never evidence that source facts were valid. Cooperative source_deadline narrows each inner timeout and prevents further requests/results after expiry. A stuck DNS/slow response cannot block the parent cancellation loop.

## Private bounded host channel

Extend the contained process runner with an opt-in typed host monitor created by the actual installed controller factory, not an arbitrary config callback/import. Its parent parser observes bounded stdout chunks directly from the runner drain; parent cancellation reads only bounded in-memory monitor state and monotonic time, with no network, Git or journal operations. The actual child PID is delivered from successful native process creation to the monitor independently of channel contents. No model response, log substring or source payload establishes a heartbeat or completion.

The fixed host child exclusively uses stdout for versioned newline-delimited control frames. Set its control stdout handle noninheritable before launching any role. All model/check/Git child stdout/stderr are redirected into their own captures; native launch inheritance must not leak the control handle. Frames carry a fresh parent session nonce, actual owner UUID, actual child PID, strictly increasing sequence, fixed domain(groups), fixed phase/source identifier, host phase UUID and closed start/end event. Frame length, parser buffer and retained phase/task counts have explicit bounds. Invalid framing/nonce/PID/sequence/domain/phase order, partial final frame, reader failure or unconfirmed cleanup fences the worker; no frame can authorize a role or reset an owner. Avoid private paths, prose, credentials and task/source contents in this channel. Child errors emit fixed categories only.

A start frame arms exactly one original phase deadline. Repeated start/heartbeat frames with the same phase UUID never extend it. A new source collection may start only after the prior source phase ended under its original deadline. Host phase end changes only parent scheduling; the actual child must still independently revalidate private files/source/operation deadlines before any claim or effect. If an original run task deadline exists, every later phase is capped by that unchanged deadline across source/clone/role/check/publication phases and new action UUIDs. Model/check time limits remain finite and independently capped by their unchanged actual profiles and admitted task/role budgets.

## Lifecycle and integration

One persistent child may span ticks; parent watch has no arbitrary short whole-session timeout, but requires the typed monitor, mandatory cancellation and bounded capture. Parent startup before the first valid frame is bounded. Parent explicitly kills and joins the complete process tree within five seconds after phase/task expiry, cancellation, parser failure or shutdown. Inspect stdout EOF, reader completion and actual cleanup; uncertain teardown never grants retry or resource release. Before exposing grouped work, the actual CLI must route collection through this boundary; a test that directly invokes PreparationContext or a fake clock only proves cooperative refusal.

Required tests: actual contained child blocked beyond a short source-phase deadline; actual descendant late-write/marker cannot survive teardown; same UUID repeated frames cannot renew the deadline; wrong nonce/PID/sequence/domain/oversized/partial frames refuse; parent cancellation makes no source/J calls; actual role output cannot write the control channel; arbitrary serialized source/monitor config cannot create authority; actual source expiry leaves J unchanged and never reaches a role/claim. Keep default process/source APIs behavior and portable CI; native Linux/macOS qualification remains deferred by the Windows release scope. Exact integration/spec/dev/test/installed pilot/PR/main acceptance still required.


## Closed task identity and original deadline binding

The parent factory loads and pins the actual private installation/group/pipeline/executor configuration before child creation, outside the cancellation callback. Its monitor receives that actual normalized allowlist, authorization/profile fingerprints and original finite task/role limits through a typed internal factory; caller JSON cannot construct it. A private policy change fences the old session; it does not silently replace its accepted policy hash or grow an existing task budget. Capacity-only runtime reconfiguration is independently revalidated by the controller outside cancellation and may register a new allowed snapshot for NEW tasks only; an existing run retains its original identity, policy/budget and deadline.

Every frame has exact common fields version=1, domain=groups, session_id, owner_id, pid, sequence and event. UUIDs are canonical; sequence starts1 and increases exactly1; unknown fields refuse. hello has only common fields. idle adds only wake_after_seconds. phase_start/end add phase_id, phase_kind, task_key; phase_kind is source, preparation, role, check or publication. task_key is null only for unclaimed source collection and otherwise equals a registered immutable run_id. phase_start additionally carries its finite requested_seconds, capped by parent-known fixed source60, unchanged actual role/profile/action limits and original remaining task budget. phase_end cannot add a timeout or new identity. task_begin adds exactly task_binding; task_end adds exactly run_id. No free prose/output is accepted. Role/check/publication phases require an active matching task and their original phase UUID; task_end requires no open phase.

The exact task_binding is installation_id, run_id, repository, issue, task_id, policy_sha256, authorization_sha256, profile_sha256, admitted_utc, deadline_utc and task_timeout_seconds. The child host encoder reads these ORIGINAL fields from the actual successfully claimed canonicalJ row in the same persistent child, after its actual transaction and before any workspace/role effect. It never encodes a model result or caller-provided admission as this binding. The parent checks installation/allowlist/fingerprints/limits against its held actual private snapshot; deadline_utc must equal admitted_utc plus that exact unchanged task_timeout_seconds, and admission cannot predate this child session or lie in the future. Parent creation records actual monotonic and UTC together; original UTC deadline maps to a monotonic ceiling using the earliest of its first mapping, unchanged configured task budget and current remaining UTC budget. Backward/uncertain UTC observation fences; later forward movement may shorten, never extend.

The monitor retains the entire first binding under run_id for the rest of that child lifetime; duplicate task_begin or changed identity/UTC/budget under any later phase/action UUID refuses. Every task phase carries that run_id and is capped by its unchanged retained deadline, including source refresh. Parent cancellation uses only this retained in-memory data; it never queries J or accepts a serialized graph as authority. Parent observation of task_begin is supervision only, not an acknowledgment of the claim or its resource lease. The child still owns that actual claim; expiry/EOF cannot transfer it or release unknown effects. Bound the session registry to4096 run IDs; at that boundary finish/clean up the current run, emit idle/end and retire the child before admitting another, rather than forgetting a prior run deadline. This is a retention limit per child lifetime, not a two-task execution cap.

## Total supervision between phases

The first valid hello must arrive within10 seconds of actual native process creation. After hello, phase_end or task_end, the next legitimate phase_start/task_begin/idle/session_end must arrive within5 seconds, additionally capped by any unchanged active task deadline. A phase_end never leaves an infinite unsupervised state. idle is allowed only with no open phase and no active task; wake_after_seconds must be1..60 and no greater than the actual configured polling interval. Idle arms a finite monotonic ceiling of wake_after_seconds+5 (maximum65 seconds). Next source phase or deliberate idle frame must arrive before it; a silent live child is killed. Repeated idle cannot cover an active task/source phase. session_end is allowed only with no open phase/active task and begins a five-second normal-exit ceiling. Normal CLI once completion must emit session_end then exit0 with full EOF/confirmed cleanup. Unexpected EOF, child exit, missing next frame, partial frame, nonzero exit or live child after an armed idle/interphase/end deadline fences the worker. Process termination/cancellation coverage is active in ALL startup/phase/interphase/idle/end states.

Add concrete fault tests for silent startup, phase_end followed by a silent live child, missing next frame, unexpected EOF/exit, idle while task/phase is active, deadline preservation across source/preparation/role/action UUID transitions, duplicate task_begin with a changed original deadline, and task-binding mismatch against the actual parent-loaded private snapshot.


## Concrete member and channel bounds

Both phase_start and phase_end additionally carry action_id, member and member_sha256 and profile_sha256; phase_end must exactly match every identity field of the original start and cannot provide requested_seconds. For an unclaimed source phase, action_id/member_sha256/profile_sha256 are null and member is collect_source; the parent ceiling is60 seconds. For role phases, action_id is the actual host attempt/action UUID, member is exactly one of the six privately resolved group roles and profile_sha256 is that role's exact actual normalized profile fingerprint. member_sha256 is the same fingerprint. The parent selects that MEMBER profile, never a caller-requested profile or another role's larger limit, and caps requested_seconds by its original timeout, actual admitted role timeout and unchanged task deadline. Unknown role, member/profile disagreement or role not belonging to the registered immutable task refuses before accepting the phase.

For check phases, action_id is its actual host check UUID, member is the exact configured check ID, member_sha256 is digest_manifest of that actual normalized private check and profile_sha256 is the original selected executor profile fingerprint. The parent requires exact private membership/hash and caps by that check timeout, original admitted role timeout and unchanged task deadline. For preparation/publication, action_id is its actual claimed host action/effect UUID; member is respectively initial_clone or pipeline_publication, profile_sha256 is the original selected executor profile fingerprint, and member_sha256 is digest_manifest({kind:member,task_policy:actual_parent_task_policy}). These two fixed host actions use an explicit conservative60-second ceiling, additionally capped by original task remaining time. End frames and new action UUIDs cannot select another member or enlarge a retained task budget. Add mismatch tests for role/member/profile/check/action category, including substituting the slowest role for another's shorter limit. These monitor limits never authorize the child action itself.

Read/drain chunk maximum65536 bytes; a complete frame including newline must be at most4096 bytes; retained unfinished parser line maximum4095 bytes. Reject oversized chunks/lines, invalid UTF-8, blank lines, duplicate/unknown JSON keys, noninteger/bool sequence/PID/limits, or sequence beyond signed64 immediately. Parse at most the one bounded chunk at a time. Keep one open phase and one active run per worker child; independent children are scheduled by actual resource admission, with no installation two-task cap. Remember at most4096 original run bindings and65536 completed/active phase UUIDs per child lifetime; every repeated phase UUID refuses even after phase_end. Before admitting a new task, retire an idle child when its remaining retention budget cannot accommodate that task's actual bounded phase budget. If a configured task cannot fit in a fresh session, refuse it as configuration-unavailable before claiming. Any actual overflow, unexpected extra phase or more than100 frames in a monotonic one-second bucket fences/kills the child; never discard older task/phase bindings or release its unknown claims to make room. Session lifetime total frame cap1000000; retire at a clean idle boundary before it, with overflow always fenced. stderr/raw stdout log retention remains independently bounded; monitor state is consumed from actual drain bytes, never a captured prefix re-imported as authority.


For a CLAIMED-task source refresh, phase_kind=source, task_key is exactly the currently active retained run_id, action_id=null (this is a read-only collection, not a new SQL execution effect), member=refresh_source, profile_sha256 equals that run's original selected executor profile fingerprint, and member_sha256=digest_manifest({kind:refresh_source,task_policy:actual_parent_task_policy}). The parent looks up the unchanged retained task and its original private task-policy/profile binding; unknown/retired run, profile/member hash mismatch, non-null action_id or an already open phase refuses. Its requested_seconds is capped by60 AND the unchanged original task remaining deadline. The fresh phase UUID cannot alter the original task binding, policy, budgets or deadline. End exactly matches these fields. A refresh is allowed only between actions with no other open phase; blocking reads performed inside an already bounded role/action remain under that action's stricter original ceiling and cannot emit a nested phase that resets it. Required tests include a positive active-run refresh, wrong-run/member/profile/hash/action rejection and a refresh followed by a new role/action UUID still expiring at the ORIGINAL task deadline.
