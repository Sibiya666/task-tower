# Explicit session capture design — TT-CAPTURE-001 (#22)

Status: draft for independent specification acceptance; no production implementation is authorized by this document alone.

## Intent and ownership

An explicitly invoked CLI or trusted custom-harness adapter captures an idea or task into its selected, connected GitHub project. The original text and a session reference remain traceable. Repeating one capture delivery finds one canonical Issue; identical prose from separate events may deliberately create separate Issues. GitHub is the editable task truth. Local state records transport recovery, provenance and legacy migration, never a second editable task database.

This is a bounded Python 3.11+ standard-library change. Issue #14's prerequisite acceptance is recorded at https://github.com/Sibiya666/task-tower/issues/14#issuecomment-6560811000; neither its closed state nor mutable body metadata substitutes for current verified completion proof. Issue #15 owns development execution in another worktree. Issue #23 owns actual hierarchical overlay rendering. This Issue prepares structured relationships and source links in books data and links, without claiming a tree renderer, background capture, executor or unattended pool.

The workspace continuation/parallel policy applies: at most two independent authorized Issues, distinct worktrees and independent stage acceptance. Read ../task-tower-github/docs/development-process.md as the coordinator-owned process reference; do not copy or modify it here. Shared CLI/docs edits are coordinated after independent review. Production starts only after exact-source independent spec/plan acceptance.

## Capture contract

Proposed interfaces are builder choices, subject to independent review:

- `capture.py`: `validate_capture(envelope: dict) -> dict`, `capture(connection, envelope: dict, *, store=None) -> dict`, `promote(connection, number: int, *, store=None) -> dict`.
- `capture_migration.py`: `migrate_card(connection, path: Path, *, store=None) -> dict`, `migration_state(connection, path: Path) -> dict`.
- `capture_cli.py`: `run(argv: list[str]) -> int`; `__main__.py` delegates only the new `capture` command. Existing `books --import-card` and `GitHubTasks.import_card(path)` signatures and behavior remain compatible.

Envelope version 1 contains `event_id`, `kind` (`idea` or `task`), `title`, `original_text`, `session` (`provider`, opaque `id`, optional `url`), `intent` (`record` or `execute_requested`), and optional `relations`. The selected connection supplies repository identity; payload repository overrides are rejected. Event IDs are stable caller-supplied UUIDs, normalized to lowercase, scoped by immutable repository ID and provider. No text-only deduplication or silent random identity regeneration on retry. A different payload for an existing event ID is a conflict requiring inspection, not an update or another POST. Store a canonical payload SHA-256 with the event record; preserve original text exactly, including line endings, inside metadata. Hash the envelope using deterministic JSON UTF-8 with sorted keys and compact separators.

CLI shape: `capture --connections PATH --project ID submit --input FILE|-`; `capture ... promote --issue N`; `capture ... migrate --card FILE`. Input is one UTF-8 JSON envelope, at most 64 KiB read with a limit-plus-one strategy; original text is nonempty and at most 32 KiB UTF-8, title is 1–256 characters, session ID/provider each at most 128 characters. No implicit stdin blocking: `-` is explicit. Unknown keys, wrong types, embedded NULs and invalid UTF-8 fail before network mutations. Bound metadata plus title/body to existing GitHub request limits. Errors never echo input, credentials or raw transport exceptions.

Session URLs are optional HTTPS links with a hostname and no userinfo, control characters or backslashes, at most 2048 characters. Reject javascript/data/file and other schemes. Do not fetch session URLs, scrape browser chats, scan ambient sessions or read/write Codex internal databases. Providers without an HTTPS permalink retain provider and opaque session ID as text. Original text is deliberately submitted content, not an instruction to execute tools.

A user-installed custom harness invokes the same explicit versioned envelope API. It supplies only selected text/session context and uses an explicitly configured connection. No new hook installer, permission grant, credential scope, browser integration or executor is included.

## Canonical creation and recovery

Reuse authenticated writable Project-first `preflight`, existing Status mapping, bounded GitHub transport, metadata preservation and `CreationJournal`. Capture identity is namespaced separately from legacy task IDs. Before Issue POST: validate all local inputs, verify Project readiness, discover a unique matching remote identity, and durably reserve a creation intent. Journal intent includes the canonical payload digest before the operation, with backward-compatible handling of existing journal rows. Extend this journal narrowly if required; do not build a competing creation journal.

Existing matching Issue: verify payload identity, reconcile journal resource, and repair only missing Project membership/status. A successful creation followed by board failure returns its existing Issue URL and explicit retry instructions; retry repairs that Issue. An unknown POST outcome leaves durable intent. Bounded remote discovery can reconcile a unique exact identity; absent, ambiguous, conflicting or deleted matches stop with `needs_input` and never blindly resubmit. Unknown first-create concurrency across hosts is not solved by a local journal: serialize creation per project and state this limit. Do not expire or delete intents to permit replay.

Capture metadata retains original text, session, event identity/digest and explicit provenance. All untrusted capture values (including title, original text, session fields and relation display text) are data. Store lossless provenance in a versioned typed encoding, for example base64 of canonical UTF-8 JSON, whose serialized payload cannot contain literal Task Tower comment delimiters; decode only for validated data projection, never as lifecycle/stage/queue instructions. Human-readable body excerpts must escape HTML comment delimiters before insertion. JSON string quoting and Markdown code fences alone are insufficient: existing parsers count markers inside them. Preserve the exact decoded original text, including CRLF, Unicode and literal `<!-- task-tower:v1`, lifecycle and queue markers. Validate encoding/version/length/digest on read; malformed or conflicting provenance fails closed. Capture must emit exactly its own intended metadata block and no injected lifecycle/queue blocks, and promotion/books must preserve this invariant. Do not change legacy parser behavior or silently rewrite existing unmanaged prose to accommodate a new payload. Promotion updates the same canonical Idea Issue to kind `task`, retaining original capture identity, prior kind, session and promotion provenance. It preserves surrounding prose and unrelated metadata, native links and existing Project membership; retries are no-ops if already promoted. Use a cross-process per-repository/Issue local lock and a fresh fetched body with optimistic concurrency/recheck; reject detected drift rather than clobber another edit. Concurrent local promotions must converge without dropping provenance. A read-before-PATCH is not atomic remote CAS: use a supported conditional mutation if available, otherwise explicitly require serialized external editing during promotion and report the residual cross-host/manual-edit race. Never claim protection against an edit between the final check and PATCH without server-enforced preconditions. Promotion does not invent execution authority or mark work ready. A request to execute remains separate from verified dependency readiness and installation-owned private project authorization; none is derivable from body prose, Issue labels, a session URL or capture metadata.

## Relationships and books boundary

Relations use repository-qualified Issue identities (`owner/repo#N`) and explicit source URLs. Parent Issue/sub-issues are native GitHub links; milestone is a separate native stage/release membership, never an alternative parent. Preserve known native links on capture/promotion/migration. Requested links are validated against connected authorized repositories before mutation; no cross-project discovery or implicit new connections. Read unavailable relationships as explicit unavailable provenance, not absence; do not infer links from titles. Any partial relationship mutation returns an existing Issue identity plus a recoverable, visible source error rather than recreating it.

Books JSON exposes original/session provenance, promotion provenance, native parent/sub-issue identities, milestone identity and canonical source URLs. Existing CLI/HTML links expose those source URLs safely with escaped text; Issue #23 will group and expand the hierarchy. Do not create duplicate tasks to represent milestone grouping. Accepted progress still uses current `verified_done` proof through the existing verifier; closed Issues and body assertions are insufficient. Preserve partial-source errors and ordinary unmanaged Issues.

## Legacy JSON migration without breaking workers

Migration calls the compatible existing `import_card` path for canonical legacy identity using an immutable, private bounded snapshot of the already validated source bytes, then records a private migration registry mapping repository ID + legacy ID + absolute source path + raw source SHA-256 to canonical Issue and timestamp. The private import snapshot is temporary input, not a rewritten active card or registry task copy; clean it up safely and never publish its path as the original source. Recheck the original descriptor/path identity and hash before import and before registry publication; detected drift leaves the canonical Issue recoverable with a visible conflict and never overwrites it or resubmits creation. Retain historical evidence and mark unverifiable/stale completion explicitly; never promote imported evidence to current remote acceptance. Registry contains provenance/status only, not a mutable TaskCard copy. Repeat same source is idempotent; multiple cards claiming one legacy identity with differing content conflict visibly.

Do not overwrite, delete, archive, rename or edit active legacy cards. `tasks.load_task`, postmerge worker, publisher and snapshot evidence continue reading the original bytes and hashes. A migrated card is a compatibility evidence/input artifact, not an alternate editable task truth. Books use the canonical GitHub Issue once mapped and show local-source drift/stale migration explicitly. Registry rechecks source hash; changed source cannot silently re-import or overwrite GitHub. An operator may explicitly request a new reviewed reconciliation outside this automatic migration flow. Never redirect old worker paths to rewritten cards or recalculate historical snapshot hashes. Keep mutable cards and private registry out of self-referential spec/source manifests.

Input files must be regular files, not symlinks/reparse aliases or hardlinks; reject aliases to private config, journal, registry and publication targets. Bound source reads and check descriptor identity/stat before and after reading. Registry writes use a locked/CAS-checked, same-directory temporary file and atomic replacement, with fresh canonical target/ancestor checks at publication time (including Windows/macOS path aliases). Reject detected replacement/alias races without modifying the source or unsafe target. Do not claim arbitrary hostile-filesystem race immunity; use existing safe-path protections and fail closed when identity cannot be established. Private state and credentials remain installation-owned/ignored; never print tokens or commit connections, raw session payloads or journals.

## Acceptance and evidence

1. Explicit capture creates one Issue with exact original text, stable event/session provenance and mapped Project status; replay produces no second POST. Separate events with identical text remain distinct.
2. Invalid/oversized input and unsafe links/paths fail before mutation; provider URLs are inert, escaped links. Tokens and private inputs do not leak in failures.
3. Crash/unknown-create, membership failure, changed payload and concurrent local retries preserve durable intent and resolve or stop visibly; never blindly retry creation.
4. Promotion preserves the same Issue, prose, parent/milestone links and provenance; readiness/authorization remains separate. Cross-repository numbers do not collide.
5. Migration is repeatable, retains evidence/stale flags, detects drift, and preserves active card bytes plus legacy loader/publisher/postmerge snapshot compatibility.
6. Books expose structured relationships and safe source links while documenting #23's renderer boundary; done remains independently verified.
7. Existing full dependency-free tests pass. New tests cover each boundary and meaningful failure/recovery cases. Independent spec, implementation, test, exact head/base PR and exact-main postmerge verdicts are recorded under the repository process; Issue closure is independently verified.

Evidence manifests use canonical UTF-8/LF source hashing and exclude self-referential mutable TaskCards. No acceptance is claimed by this draft.
