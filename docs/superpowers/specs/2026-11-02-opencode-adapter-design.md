V2 run has no `--dir`; set the child `PWD` to the exact worktree so inherited PWD cannot redirect the session. It does not install/start a persistent service. Never log its generated credential. V2's default managed service, external HTTP attachment and arbitrary port discovery are prohibited. ### Bounded discovery closure and host verification

Implement the finite source-qualified surface table for exactly V2.2.5, with source-audit artifact anchors to `config/discovery.ts`, `config.ts`, `config/plugin/source.ts`, `plugin/source-directory.ts`, CLI startup/config/migration/updater, global roots and standalone ownership. The table enumerates every path family and environment selector these paths use. Qualification must verify this coverage from tagged source; a source family absent from the table is unsupported, never assumed harmless. This is a supported finite subset, not proof about every possible plugin or account-dependent configuration. No general recursive home search or auth/session/database read is performed.

1. Compute actual launch worktree from already-bound run/attempt UUIDs and approved runs root. Before probe it must be prepared at exact source SHA; probe and native execution use this same cwd and effective PWD. Enumerate that directory and every lexical ancestor through the volume/filesystem root, maximum 64 ancestors, inspecting only eligible names `opencode.json`, `opencode.jsonc`, `.opencode`, `.agents`, `.claude`. Also enumerate the source-defined home `.agents`/`.claude`, global config directory, platform system directory and both macOS managed-preference candidate paths, including every absent candidate. Global config roots follow tagged XDG/home logic and approved selectors, not guessed Windows AppData paths. Any ancestor/reparse ambiguity or permission error blocks.
2. Inventory entries are tagged unions. A `missing` entry has exactly `{kind,path,role,parent_identity}` and records the nearest existing parent plus its filesystem identity and each missing path component. A `file` entry has `{kind,path,role,identity,bytes,sha256}`. A `directory` entry has `{kind,path,role,identity,members}`, where members are the sorted complete direct child list `{name,kind,identity}` including names outside the eligible subset, without reading their contents. Identity is platform-normalized `{device,file_id,kind,reparse}`; use volume/file ID on Windows and st_dev/st_ino on POSIX. Reject any symlink/junction/reparse component, hardlinked eligible file, unsafe normalization, changed identity/type, or unresolved parent; do not follow aliases. Parent directory identity does not include unrelated ancestor membership, so ordinary siblings do not create irrelevant drift.
3. The initial supported discovery subset allows reviewed nonsecret regular config files and bounded source-eligible config/agent/command/skill/plugin directory trees only when the source table supplies their exact eligible child patterns and startup interpretation. Record explicit missing eligible subdirectories as well as complete direct memberships of each inspected directory; rewalk those eligible children only. Maximum 4096 total entries, 256 members per inspected directory, depth 16 below a discovery root, 1048576 bytes per approved nonsecret file, 8388608 hashed file bytes total. Overflow, unknown entry kind or unknown config key/reference semantics blocks before native invocation, rather than truncating inventory. Do not read arbitrary files discovered by enumeration. A root containing credential-bearing or unqualified compatibility surfaces (including present home .claude/.agents without a separately source-qualified noncredential child table), configured package/local plugins, MCP startup, remote/integrated/managed settings or dynamic file/env substitutions remains unsupported initially; record their presence/metadata and reason without reading credentials or executing discovery. Keep user config intact. Future support needs a new table/source+fixture qualification and accepted policy, not a generic owner assertion.
4. External roots and worktree ancestors above runs_root bind absolute paths and identities. For the as-yet absent per-attempt path, policy binds an exact-source worktree-relative inventory template and approved absence of eligible config candidates at the generated run/attempt ancestors; host collector expands this template for the actual UUIDs, records real identities after Git preparation, and compares all contents/memberships/absences to the approved template. Run-created manifest/log/request files are outside native discovery roots and excluded only by this explicit source-qualified rule. A changed source SHA requires renewed source-template acceptance. An eligible source appearing in any new run/attempt ancestor blocks even if all original config hashes match. Never qualify against only the connected checkout or a generic scratch cwd.
5. `collect_opencode_discovery(scope, *, worktree, environ) -> dict` performs the bounded read-only collection; `compare_opencode_discovery(expected, observed) -> list[str]` compares canonical path sets, missing/present states, identities, sorted memberships, nonsecret hashes and environment binding, returning specific stable reason codes. `verify_opencode_preflight(profile, *, attempt, environ) -> dict` recomputes observation before any native probe and again immediately before native execution, rechecks policy/artifact/pins/source, and supplies exact cwd/effective environment only if comparison has no findings. No placeholder callback returning True is permitted. Repeat collector if its own before/after directory identity/membership checks change during collection; at most one retry then block. Keep the exact observation digest in launch intent. Ordinary Git worktree preparation remains separately authorized; this gate precedes every OpenCode child, including --version. Existing process ownership cannot lock external user config against a malicious concurrent writer; this is immediate-before-launch drift detection under trusted-host policy, not an OS filesystem sandbox or universal TOCTOU guarantee.

## Events, completion and evidence

Parse the complete safe stdout capture incrementally after the contained process returns. Limits: 1048576 bytes per JSON line, 100000 events, 67108864 total observed stdout event bytes, 65536 bytes retained normalized event evidence, 256 characters per session ID (`ses_` plus ASCII alphanumeric/underscore/hyphen), 256 per part/message ID. Check observed byte count/truncation/EOF before parsing and read at most one bounded line at a time. Malformed UTF-8/JSON, duplicate keys, nonobject lines, ANSI/noise, over-limit buffers/counts or wrong typed known fields invalidate event proof. Raw logs/events stay private; no prompts/tool arguments/model reasoning copied into public verdicts. A too-large stream may run until the existing timeout but cannot grow stored logs past the cap; this implementation does not advertise immediate stream-limit cancellation.

One attempt binds the first valid root session ID; every emitted outer sessionID and nested part.sessionID must agree. Never infer ownership from a title/PID or adopt an unrelated session. Decode V2's emitted CLI envelope `step_start`, `step_finish`, `text`, `tool_use`, `error`, not its internal bus events. Tool parts use partID as well as tool-call id; step/text parts use id. Unknown event names are retained only as bounded type/count diagnostics and invalidate successful event completion. Identical duplicate event identities are idempotent; conflicting duplicate part terminal content fails. Aggregate only completed text/step/tool metadata, never execute tool content. Session errors and tool error states prevent completion. Require final assistant step `step_finish` with reason `stop`, no unfinished started step, EOF proved, valid bound local result, zero exit and confirmed cleanup. V2 may reconcile missing text/tool/step lines after its live stream: accept reordered projections belonging to the same known assistant message, including text after its step_finish, but reject a new assistant step after the terminal stop unless that step also completes and the final step stops. A terminal marker alone, text that says “done”, exit zero, `tool-calls`/length/error finish, or a missing terminal marker cannot complete. Incomplete output remains failed/unverified, never repaired by Task Tower reading native databases or replaying a prompt. The CLI's own in-process projection reconciliation is not Task Tower resume authority.

Local result schema stays exactly `{version,run_id,attempt_id,source_sha,status,summary}` with existing 65536-byte file and 4096-byte UTF-8 summary limits, allowed statuses completed/failed/needs_input, no duplicate/extra keys. Do not manufacture a completed result from stdout. `execution_completed` remains separate from independent development/test/PR/postmerge acceptance. Native observed actual model/provider may be recorded only if already supplied in nonsecret native execution evidence; otherwise `actual_model_observed=false`. Never infer model from a default, select one, or claim it was verified from flags alone.

Capabilities retain configured/executable/probed/verified/events/resume meanings. New profile registration has `probed=false`, `verified=false`, `events=false`, `resume=false`. Successful version probe changes only probed; native task plus distinct reviewer evidence qualified for that exact binary/policy/source can support verified/events. Fixture/parser tests remain separate evidence. Report timeout/cancel as local contained-process controls, not verified remote session abort.
