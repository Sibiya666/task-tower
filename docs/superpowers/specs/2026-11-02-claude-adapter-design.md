## Installation policy and invocation

Extend executor configuration version 1 additively with `kind: "claude"`. All existing required profile fields, private-path checks, pins, source authority, allowlists and fingerprints apply. Claude requires a single absolute native executable argv element, `approve_for_me: false`, `trusted: false`, and a required strict `claude` object with exactly `version`, `role`, `max_budget_usd`, `stream_max_bytes`, `line_max_bytes`. Version must be `2.1.302`; role is `implementer` or `reviewer`; budget is a positive decimal string with at most two fractional digits in `(0,100]`; stream cap integer `65536..67108864`; line cap integer `4096..1048576` and no greater than stream cap. Reject booleans, nonfinite values, unknown fields and all Claude options on non-Claude profiles. Existing profile fingerprints bind these fields.

Fixed invocation: executable, `-p`, `--output-format stream-json`, `--verbose`, `--safe-mode`, `--permission-mode manual`, `--permission-prompts none`, `--strict-mcp-config`, `--mcp-config EMPTY_MCP_PATH`, `--no-chrome`, `--session-id ATTEMPT_UUID`, `--max-budget-usd PROFILE_BUDGET`, `--json-schema SCHEMA_JSON`, `--tools TOOL_LIST`, `--allowedTools ALLOW_LIST`, followed by one generated prompt. Use argument arrays and the existing attempt worktree cwd; no shell interpolation. Write immutable private empty MCP config `{ "mcpServers": {} }` and its digest before launch. Prompt includes the pinned instruction content and execution request content, not merely paths outside the working directory; both are task context, never configuration authority. Preserve the default system prompt. Schema comes from existing `result_schema(attempt)`.

Implementer tool and allow lists are exactly `Read,Edit,Write,Glob,Grep`; reviewer lists exactly `Read,Glob,Grep`. Do not enable Bash, PowerShell, Agent, Skill, WebFetch/WebSearch, MCP, background, remote/cloud or publication tools. No model, fallback-model, effort, bypass, acceptEdits, auto or restricted flag. Safe mode avoids ordinary hooks/plugins/repository customizations while retaining existing model/auth handling. Restricted mode is deliberately excluded because it ignores settings that may select the existing model. Bare mode is excluded because subscription OAuth/keychain login is unavailable there. Managed policy can still run hooks/helpers and affect model/permissions; record this boundary without inspecting secret configuration. An installation unable to approve its existing managed policy is blocked, not silently weakened.

Tool allow rules are explicit profile policy for this bounded file task, not an OS sandbox. Existing filesystem permissions, managed policy and CLI authentication remain. Never promise confinement of credentials/network or arbitrary filesystem access. File reads/edits outside the target or mutations of protected Git/settings paths must be refused by task instructions and reviewed; a worktree is not a sandbox. No automatic credential scopes, settings edits, install/update or model switch. Strip `GH_TOKEN` and `GITHUB_TOKEN` case-insensitively from every child including probes; preserve the host environment.

For every Claude child, including version/help probes, use a fresh environment from `claude_child_environment(environ)`: first apply existing token stripping, remove all case-insensitive aliases of `DISABLE_UPDATES` and `FORCE_AUTOUPDATE_PLUGINS`, then set canonical `DISABLE_UPDATES=1`. Remove the force-plugin-update override entirely; do not invent a meaning for value `0`. Never mutate the host or common legacy child environment. Preserve all other variables, including existing authentication, model and telemetry controls; no new telemetry setting is introduced.

The guard is fixed invocation policy, never profile/Issue input. Explicitly constructing the child mapping ensures an inherited `DISABLE_UPDATES=0` or case alias cannot override the canonical guard in that supplied mapping on either case-sensitive POSIX or case-insensitive Windows. Upstream precedence documentation says settings-file `env` values replace inherited values in most sessions; it does not establish an exception for this update guard. Before each concrete probe/pilot, perform a bounded read-only preflight of known applicable local settings: the selected config directory's user settings, project/local settings applicable to the actual invocation worktree and its repository, explicit invocation settings if any, and known platform-local managed settings sources. Inspect only case-insensitive update-related `env` keys; retain sanitized source identities, presence/findings and fingerprints privately, never credentials or complete settings contents. Block an observed override that disables the guard or enables forced plugin updates, and block an unreadable relevant local source. Recheck the source fingerprints immediately before launch; a changed source requires a fresh preflight.

If no conflict is observed in these local sources, proceed with the guarded child mapping under the original managed-policy trust boundary. The preflight does not establish all remote or future managed policy, does not require a new human attestation for hypothetical behavior, and is not an absolute OS/update guarantee. Newly observed conflicting managed behavior remains a real blocker. Do not inspect credentials, change global settings or mutate policy to pass the preflight. No update/install command is used as a probe, and no claim is made that arbitrary approved managed hooks cannot run external commands.

Wall clock `timeout_seconds`, per-stream stored log caps and existing five-second cleanup deadline remain hard local process/storage bounds. Budget is an approximate Claude cost stopping condition that can overshoot and is not a billing guarantee. No turn limit claim. Stream/line caps bound parser observation independently of prefix log storage. Exceeding a cap invalidates success and requests contained termination; timeout/cancel/uncertain cleanup always takes precedence over a model result.

## Streaming and result contract

Add an optional `stdout_observer` callback to `processes.run_command`, preserving all existing callers. Drain all observed bytes through the callback independently of capped log prefixes; retain current hashes/counts/truncation/tail evidence. Callback execution must have bounded work/memory, never log raw output, and never break draining. Its failure is recorded, requests termination through the existing poll loop and prevents success. Do not parse only stored prefixes, buffer the full transcript, or block the child on a consumer that stops reading.

Create a dedicated Claude incremental NDJSON parser. Bounds are total observed stdout bytes and incomplete/complete line bytes; strict UTF-8, JSON object root and duplicate-key rejection apply to every line. Permit CRLF and a final nonempty line without newline. Ignore blank lines only; malformed JSON/UTF-8, oversize, nonobject, or observer exception invalidates the attempt. Recognized harmless system/assistant/user/rate-limit/progress events may be counted without retaining content; unknown event types are counted as unknown and never interpreted as success. Unknown result subtype is failure. Record only bounded counts, session UUID, terminal subtype, denial count and validation flags publicly; raw content remains private.

Require exactly one `system/init` with `session_id == attempt_id` before any result and exactly one final `result` with the same session ID, main-conversation ownership where applicable, `subtype == "success"`, `is_error is False`, empty `permission_denials`, and a `structured_output` object passing the existing exact local result schema/binding validation. A denial system event, nonempty denial array, initialization/configuration error, duplicate init/result, mismatched session, any nonblank event after final result, missing required fields, truncated/unobserved tail or missing final result prevents execution_completed. Events may have additive upstream metadata, but the nested result retains existing exact keys, UTF-8 byte limits and run/attempt/source bindings. Never trust model summary, raw text `result`, exit zero, reported cost or a session file as acceptance.

On valid stream, atomically create `result.json` using exclusive private-file creation and run the existing validator. Require process exit zero, confirmed cleanup, fully observed stdout EOF and parser success before mapping nested completed/failed/needs_input. Permission denial maps to needs_input with bounded reason even if exit zero; malformed/protocol-invalid output maps failed. Unknown cleanup/ownership stays unknown. Store parser evidence in a separate private `claude-events.json` and queue evidence digest; absence/collision/unsafe file or failed write prevents success. Record actual CLI-reported model metadata privately if present, without treating it as user-selected or revealing auth/session content publicly.

## Cancellation, resume and reconciliation

Reuse existing durable admission, pre-effect authority/dependency revalidation, owner exclusion, queue cancellation and Windows Job/POSIX process-group cleanup. No new schema migration or journal reset. Profiles revoked or modified block launch; status/cancel remain available. Reconciliation inspects retained manifest/request/process/parser/result digests and known session UUID; it does not invoke Claude. CLI resume exists upstream but this adapter advertises `resume: false`, `automatic_resume: false` and never passes continue/resume/fork-session. Unknown or started outcomes cannot be replayed through retry. Only existing explicit proven-no-child prelaunch retry applies, retaining attempt evidence. A read-only reconciliation report is not completion proof or permission to clear uncertainty.

Capabilities must distinguish configured, executable, probed, version_supported, protocol_validated, installed_execution_verified, independent_review_verified and per-OS evidence. Existing legacy capability keys retain their meaning. `events` becomes true only for Claude after actual protocol evidence; fixtures must be labeled fixture evidence, never installed execution. No result sets accepted/done.
