# Bootstrap и первая задача Task Tower

Статус: реализация по поручению владельца от 2026-11-01. Родительская архитектура: 2026-11-01-agent-development-architecture-design.md.

## Результат

После git clone пользователь запускает bootstrap.py установленным Python 3.11+. Скрипт определяет Windows/macOS/Linux, предлагает Codex, Claude Code, OpenCode или собственный адаптер, проверяет исполняемый файл и сохраняет выбор локально. При повторном запуске использует выбор; --harness меняет его. Отсутствие Python объясняют тонкие start.cmd/start.sh. Установки, покупки, изменение авторизации и включение обходов разрешений автоматически не выполняются.

Общий bootstrap не импортирует Windows overlay. На Windows предлагает запуск overlay только отдельным флагом; на остальных ОС ясно сообщает отсутствие native overlay. Этот этап запускает harness в текущем терминале; полноценная телеметрия других harness и UI трёх книг остаются отдельными этапами.

## Harness-контракт v1

Builtins: codex с начальным prompt, claude с начальным prompt, opencode с --prompt. cwd всегда выбранный проект. Нужен установленный исполняемый файл, без shell=True. Windows .cmd/.bat/.ps1 не запускаются неявно: сообщить необходимость native executable или custom adapter с явным интерпретатором. CLI --help/--version не являются проверкой авторизации и модели. Пользователь использует существующую авторизацию harness, ключи bootstrap не читает.

Custom descriptor: JSON с version=1, id, launch_argv как непустым массивом строк и capabilities. Разрешённые подстановки — {project}, {instructions}; оба пути подставляются отдельными аргументами без shell expansion. Capability interactive_launch=true обязательна. Параметры callbacks/structured-events/resume/independent-review/autonomous-merge не обещаются v1. Descriptor — доверенная исполняемая конфигурация, запуск только после явного выбора пользователя.

## Superpowers и настройки

Для запуска необходим реальный SKILL.md Superpowers: --superpowers PATH, сохранённый путь либо известный проектный путь. Содержимое хешируется и проверяется снова перед запуском. Новая hash-версия требует явной перенастройки с --superpowers; молчаливого обновления нет. Проектные AGENTS.md/CLAUDE.md не перезаписываются. В .task-tower/context.md генерируется контекст с указанием проекта и skill, который harness получает через initial prompt. Это доставка инструкций, не доказательство исполнения навыка.

Локальные настройки .task-tower/config.json, абсолютные пути и контекст исключены Git. Запись атомарная, не следует hardlink, нельзя писать через symlink-каталог .task-tower. --dry-run ничего не записывает и не запускает; --configure-only сохраняет, но не запускает. Non-TTY требует --harness или сохранённый выбор и явный --launch для исполнения; обычный интерактивный запуск предлагает выбор и запускает. --launch и --configure-only/--dry-run взаимоисключающие.

## Проектная задача TT-BOOTSTRAP-001

Для проверки процесса сохраняем карточку docs/tasks/TT-BOOTSTRAP-001.json и CLI `task show PATH`, `task accept PATH --stage STAGE --reviewer ID --evidence FILE`. Постоянное хранилище и автоматический диспетчер не подменяются JSON-файлом: это пилотный адаптер карточки. Он хранит этапы spec, development, test, postmerge, разных исполнителя/приёмщика, ссылки и SHA-256 свидетельств; запрещает пропуск этапов и самоприёмку. Одобренные свидетельства перепроверяются перед переходом. postmerge требует явно указанного коммита, содержащегося в локальной main; задача становится done только после этой приёмки. До main статус awaiting_merge, а не done. Кто вызывает CLI и честность reviewer ID проверяются организационно; аутентификация ролей и автоматическое назначение ещё не реализованы.

При изменении свидетельства приёмка не считается актуальной; это не защищённый CI gate. Слияния, push и commit без отдельного поручения не выполняются (AGENTS.md). Спеку, разработку и тесты принимают независимые агенты; финальная приёмка после main ждёт реального слияния.

## Приёмка

- Реальные subprocess-тесты bootstrap с fixture harness; установка моделей не нужна.
- Сохранение/повторный выбор/custom descriptor/пути с пробелами и Unicode; отсутствие инструмента/skill и изменённый skill дают объяснимый отказ.
- Dry-run и configure-only не вызывают harness; запуск получает cwd и контекст, exit code передаётся пользователю.
- Карточка не принимает этап без свидетельств, с тем же ID исполнителя или в обход порядка; stale evidence не считается принятым; postmerge нельзя принять до main.
- Один и тот же CLI-набор тестов предусмотрен CI для Windows, Ubuntu, macOS. Здесь подтверждается только фактически выполненная ОС; CI добавляется без заявления о пройденных удалённых job.
