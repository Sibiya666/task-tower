# Overlay books design — TT-BOOKS-UI-001 (#23)

## Intent and authority

Bring the three project books into the canonical Windows overlay so a person can inspect ideas, implementation stages/features/tasks and Markdown evidence without confusing live session activity with task acceptance. GitHub Issues, native relationships, milestones and repository Markdown remain truth. Issue #22 has independently accepted main evidence and automatic closure; the coordinator verified genuine dispatcher admission for #23 before authoring this design.

The existing autonomous backlog authorization delegates routine choices and skips repeated design questions. The choices below are implementation judgments, including the optional library index syntax, not claims that the user selected that syntax. Python 3.11+ standard library, existing HTML/CSS/JavaScript, .NET/WPF Composition WebView2 and Windows PowerShell 5.1 remain the stack. No new framework, package installation, credential scope or implicit project discovery.

## Scope and constraints

- Canonical UI is `overlay/`; no second root overlay. Use `task_tower.books.aggregate` as the shared projection source for CLI and overlay.
- Three books: Ideas, Tasks, Project library. Display at most three record cards per page, including expanded feature children; group headings and navigation are not record cards. Detail view displays one selected record.
- Preserve repository-qualified Issue identity, configured project identity and immutable Markdown version identity. Do not infer relationships, blockers, results, artifact acceptance or task completion from names, arbitrary prose, closed Issues or green CI.
- Preserve all existing overlay invariants: transparent composition, minimal overview/room controls, activity lights, explicit user-decision hourglasses, unknown/stale presence, reduced motion, hit testing, 5 px drag threshold and monitor/DPI placement. Books do not change collector/executor/dispatcher contracts or write Codex internals.
- Book snapshots, private configuration, credentials, checkout paths and logs stay out of Git and WebView payloads. Public projection can contain selected source text and provenance; never serialize raw metadata/configuration/transport exceptions.

## Entry, layout and keyboard behavior

Add a “Книги проектов” action to the scene context menu, with project-scoped action in the existing tower/floor menu only when an explicit mapping to a connected project is available. A session/tower name is not a connection identity. The global action always works with all configured connections. No permanent toolbar expansion, footer or captions.

`Ctrl+B` opens the books dialog; ContextMenu/Shift+F10 opens the existing scene menu at a clamped position. The dialog uses the current window area, scrolls internally and fits the small room viewport; it must not force native resize or change stored overview/room bounds. Background scene remains transparent and visually stable. An opaque readable book surface inside the dialog is allowed; the window background remains alpha transparent. Hide scene interaction while the dialog is open without changing activity data.

Dialog controls: book selector, project selector (including all), status/state filter, Tasks grouping selector (stage/features), refresh, close, previous/next and a count/page indicator. Completed records remain selectable; no default filter discards them. Filters reset page to zero; refresh preserves valid filters and selected qualified identity, clamps the page and labels removed selection unavailable. No project connections yields a helpful disabled/configuration state, not an empty-success claim.

Use semantic buttons/selects, a labeled modal dialog, visible focus, Escape to close details first then dialog, Tab/Shift+Tab contained within the active dialog and focus restoration to the invoking element (fallback scene focus target). Enter/Space operate record/expand buttons; no bespoke keyboard-only inaccessible controls. Long Unicode text wraps. Menu/book/detail elements never initiate native dragging or floor selection. Dialog placement stays inside viewport at 340×300 and normal overview sizes.

## Shared data projection

Extend `aggregate(connections, store_factory=GitHubTasks, include_library=False, *, on_update=None)` additively. Existing `entries`, `errors`, `fetched_at` and legacy entry fields remain. Each Issue entry additionally exposes `repository`, `number`, sanitized `description`, `phase`, `blockers`, `results`, `history` and native `relationships`. Relationships are fetched for ordinary Issues too, reusing `capture.relationship_projection`; retain null (known absent) versus `{status:"unavailable"}`. Never let one malformed Issue silently erase healthy records; emit a fixed source error and retain its valid identity with unavailable details where possible.

### Progressive projection before expensive completion verification

Operational evidence measured an unchanged genuine `verified_done` dependency proof at 137.64 seconds. Therefore a 120-second overlay deadline cannot require all proofs before first rendering. The shared aggregate must order work as follows: fetch each connected project's bounded Issue listing, immediately project its known identities/titles/remote states with `verification:"pending"` and unavailable details/relationships, and call `on_update(report)` before lifecycle/native-detail/acceptance calls. Continue listing remaining projects before enriching details. Next enumerate current library/version data, then details/relationships/lifecycle, publishing usable updates between these phases; only after these base-data passes attempt sequential fresh `verified_done` for completion candidates. An interrupted detail/proof call must not erase already published identity/library data. Listing/library transport can itself fail or hit the wall-clock deadline; label unfinished sources explicitly, retain any arrived records, and do not promise that every remote source can be read within 120 seconds.

Each callback receives an independent public report snapshot. `on_update=None` retains existing synchronous CLI final-result behavior and completion semantics; the overlay supplies a callback. This is incremental reporting, not a new completion verifier or proof cache. Entries pending proof use conservative `task_status` and never `done`, even when remote closed or previous snapshots were accepted. A successful current-attempt unchanged verifier result can set `verification:"verified"` and `status:"done"`; false/error sets `verification:"unverified"` with a fixed reason. Do not reuse proof success from a prior refresh or trust declaration metadata. Pending/unfinished verification keeps overall report partial and progress explicitly unknown. Capture library/current Issue identities before starting any expensive acceptance proof; this requirement applies even when the first closed Issue has a slow proof.

Detail projection uses Issue prose with the Task Tower metadata block removed, bounded to 32 KiB UTF-8 and visibly labeled if clipped. Supported explicit metadata fields are `phase` (string), `blocked_by` (qualified Issue list), `blockers` (string list), `results` (safe source URL list), `stages` (existing accepted/pending records) and `remote_attempt` (existing structured data filtered to known public evidence/identity fields). Unknown or wrong-type detail fields produce a field-unavailable indication, never raw object serialization. Missing fields display “Не записано”; failed retrieval displays “Недоступно”. Issue body prose is rendered as plain text, never HTML/Markdown execution. Captured session provider/id and original text remain inert provenance; unknown session URLs are text only.

Use existing `issue_lifecycle` history in its comment order, exposing only status and bounded known public attempt identity/evidence fields. Do not add arbitrary-comment harvesting. History contains recorded lifecycle transitions, not an invented complete audit log. Include created/updated timestamps when GitHub supplies valid strings. Explicit source detail limits: 256 characters per phase/blocker label, 100 blockers/results/history entries each; display truncation/error indicators. Existing metadata validation and independent `verified_done` are unchanged: only the existing freshly verified completion path yields `status: done`. Stage labels are recorded claims; task accepted progress counts only `status == done`.

## Tasks hierarchy

Maintain a single normalized record map keyed by `repository#Issue`. Never duplicate a task record to represent stage and parent. Stage mode groups the filtered records by native milestone, plus “Без этапа” and “Этап недоступен”; feature mode roots records by native parent links, retaining explicit parent references when the parent is outside the filter or disconnected/unavailable. Features spanning stages retain one parent identity; each task appears once in the current projection under its own milestone. Expandable parent controls expose matching children via the shared map; absent child records appear as source-linked relationship references, not invented records. Opening a parent from a different stage changes selection/details rather than copying its task card into that stage.

Flatten visible expanded records deterministically before pagination; at most three cards across every group on a page. Root/child ordering uses qualified identity with stable numeric Issue order. Preserve orphan/unassigned records and handle cycles/self-links defensively: display each identity once and show an explicit invalid/unavailable relationship warning. Unavailable relationship data never means zero children. Parent progress shows separate known counts: verified accepted / loaded children, remote closed / loaded children, and unresolved relationships. These are loaded-snapshot counts, not implied complete feature acceptance; a parent has its own independent acceptance.

Ideas retain promoted-task linkage only when explicit provenance provides it. Same-Issue promotion from #22 changes the book while preserving identity and source history; never create a synthetic resulting task.

## Project library and explicit versions

Existing `GitHubTasks.library()` enumerates Markdown at the fetched default-branch commit. Add optional repository file `docs/task-tower-library.json`, fetched at that same commit. This is a read-only declarative repository index, not an alternate task database or execution input. Version 1 shape is `{ "version": 1, "artifacts": [...] }`. Each artifact row is exactly `{ "path": "docs/spec.md", "commit": "<40 lowercase hex>", "state": "working|accepted|superseded", "issues": ["owner/repo#42"], "milestone": null|{"repository":"owner/repo","number":3} }`. `issues` and `milestone` may be omitted and then convey no association. Paths are safe relative POSIX `.md` paths, without empty/dot/dot-dot segments, backslashes, controls or absolute paths. Associations must target explicitly connected repositories; never discover another project. A manifest row is version identity `repository:path@commit`. Verify each referenced Markdown blob exists at its declared immutable commit; unavailable versions stay visible as unavailable declarations. Deduplicate identical version identity; conflicting duplicate declarations invalidate that index visibly. Limit index to 256 KiB and 1000 rows; reject unknown keys/types/version.

Render state as “Заявлено: рабочий/принятый/заменённый” with manifest-at-commit provenance. Declared artifact accepted is never verified task Done. Link exact Markdown commit URL, repository/path, commit and explicit associations. Show multiple declared versions in the artifact detail/history; do not infer supersession edges beyond declared state. Current-tree Markdown absent from the index remains visible with state “Не указан” and its fetched immutable commit. For an indexed path at the current commit use one version card; older declared commits remain independently selectable. Missing index is normal unindexed state; unreadable/malformed index is visible unavailable state while the tree remains accessible. No filename/title heuristic, local uncommitted working-file scan or automatic artifact state mutation.

## Private bridge and refresh

Create `task_tower.overlay_books` as a bounded one-shot read-only producer, launched only by native host on explicit Books open/refresh. Private `TASK_TOWER_CONNECTIONS` environment variable supplies the existing explicit connections JSON path; no WebView-selected filesystem paths or configuration writes. Absent variable yields `unconfigured`. Resolve using existing connections/safe-path rules. The host launches its already configured Python and fixed `-m task_tower.overlay_books` argument vector from the canonical repository root. Windows quoting must preserve spaces/Unicode and use the standard escaped-argument routine or data file, never concatenate model/Issue text into shell commands. No shell, hidden permission grant or token in arguments. Credentials remain in Python host environment and existing GitHub resolver only.

Producer stdout is bounded UTF-8 newline-delimited JSON: each line is a complete versioned envelope `{kind:"books",version:1,sequence,final,state,fetched_at,entries,errors}`; sequence is a strictly increasing positive integer, final is boolean, states are `ready`, `partial`, `unavailable`, `unconfigured`. Native accepts each valid line immediately rather than waiting for process exit; a missing final line is interrupted/partial, never success. The helper emits the first known-identity projection immediately, coalesces subsequent public callback snapshots and always attempts a final frame on normal completion. Cap each line at 8 MiB, each snapshot at 10,000 entries, and the whole stream at 64 MiB/32 frames. Reserve capacity for a final frame; suppressing intermediate frames does not suppress the first identity projection. Exceeding any limit reports visible partial/unavailable and terminates the attempt; never silently claim completeness. Host loading/error envelopes use the same kind/version plus last usable data when retained and explicit state. No `projects` array; existing tower snapshot handler therefore ignores book messages. Existing per-request 2 MiB/30 s and pagination bounds remain. Host wall-clock attempt cap is 120 s, single-flight, asynchronous; terminate/reap its own helper on timeout/close and discard late outputs using attempt ID. Do not block native UI or issue concurrent refreshes. Raw stderr/exception content is never shown or persisted; fixed diagnostic codes only.

Successful or partial payload retains fetched timestamp; last payload becomes stale after 300 seconds and immediately after a failed refresh. Show fetching, partial, stale, unavailable, verification pending/unverified and last-success time separately. Timeout cannot advance freshness: retain the most recent validated partial frame from this attempt, mark it interrupted/stale with pending proofs unresolved; otherwise retain old records stale or show unavailable if none ever arrived. Last-success time changes only on a final ready frame. At new refresh invalidate old `done` proof displays immediately (pending verification), while retaining records as stale until new frames arrive. Source health is independent of session presence freshness and cannot alter room/agent state. No automatic polling or network from WebView; reopening may reuse snapshot with stale label until explicit refresh, while first open requests data.

## Native security boundary

CSP remains `connect-src 'none'`, scripts/styles local, no remote embeds or raw HTML. Render all external values with DOM textContent. Native accepts book actions only from exact trusted `https://tower.local/index.html` document origin/path without credentials/query/fragment and bounded JSON schema, keeping existing actions working. Book actions are fixed `books-refresh` and `books-open-source` (URL string only). Reject unknown fields, oversized messages and unconfigured destinations.

External opening is host-only after URI parse and allowlist: HTTPS, exact `github.com`, default port, no userinfo, query, fragment, backslash/control or encoded path traversal/separators; configured repositories only; exact `/owner/repo/issues/N`, `/pull/N`, `/milestone/N` positive-number paths, immutable `/blob/<40hex>/<safe escaped relative .md>` paths, and optionally the exact configured Project URL. Validate once against trusted configured identity, not Issue prose or payload-provided repository lists. Session/custom/other HTTPS URLs remain inert text. Block WebView navigation/new windows; do not relax current virtual-host mapping or grant tokens to WebView. Opening validated source in default browser is the only external launch; no raw command interpolation.

## Acceptance and evidence

1. Shared Python tests prove ordinary and captured Issue relationships, independent milestone/parent identity, retained unassigned/completed tasks, public-only details/history, explicit library version/state validation and no task Done from declaration/closed Issue. A controlled blocked verifier fixture must show identity and library callbacks received before it is released, with pending/unverified progress; a true released verifier may subsequently publish verified Done. No elapsed real 137-second test is required; deterministic synchronization proves the ordering.
2. Pure JavaScript tests prove deterministic cycle-safe hierarchy, independent stage grouping and parent references, mixed groups paginated to three cards, filters/page clamping, source staleness and identity collisions across projects/repos.
3. Real Edge DOM/browser interaction opens from context menu and Ctrl+B, exercises all three books, keyboard focus cycle/Escape restoration, details/history/blockers/results, unavailable and stale refresh, malicious text/links, 340×300 scrolling and unchanged background activity state. Assert no page errors or CSP regressions.
4. Actual Windows PowerShell 5.1 native composition host passes existing smoke plus Books refresh/source rejection scenarios and open/close/focus checks; capture raw native book UI screenshot with no unrelated desktop/private content. Browser-only evidence is insufficient. If native prerequisites cannot be met, record blocker and do not claim UI acceptance.
5. Run complete CLI and overlay suites, then record exact revision, environment, commands/exit codes, browser/native evidence paths and limitations in a Markdown evidence report. Independent builder/spec-plan acceptance precedes implementation, independent development/testing acceptance precedes fresh whole-diff exact head/base PR acceptance, successful CI/merge and exact-main independent postmerge/automatic Issue closure.

## Non-goals

No editing/capture/promotion UI, GitHub writes, task executor controls, project onboarding/discovery, daemon, accepted-artifact classifier, complete Git history crawler, session URL launcher, or alternate status database. Existing standalone flat HTML stays supported; this issue's hierarchy is the canonical overlay books view backed by the shared additive projection.
