# Windows Beads admission and evidence contract

Canonical task: `tt-auq.1`, parent `tt-auq`. The operator explicitly activated the seven-task Windows chain on 2026-11-05. This component supplies readiness observations and pinned public inputs; `tt-auq.2` owns live claims and stage execution.

## Outcome and boundary

Provide a standard-library Python CLI which reads an explicitly authorized installed local embedded Beads project and emits a bounded readiness packet for one selected task. Beads remains the sole task/dependency/history/claim engine. Task Tower must not create a second queue, ownership database or replacement journal. Books remains read-only and does not acquire an execution API.

A packet means `eligible_observation`, `refused` or `unknown`, never executable ownership, accepted or done. It is an observation that may become stale immediately. The stage controller must recheck current authorization, actual source identity and Beads readiness, then perform Beads' atomic claim under its real actor before any effect. JSON cannot restore a claim, process or fence. This task neither launches a harness nor closes tasks.

## Private operator configuration

Use a separate version-1 admission configuration, not TASK_TOWER_BEADS or its Books config. Exact top-level keys: `version`, `executable`, `projects`. Each project has exact keys `id`, `repository`, `directory`, `source`, `expected_head`, `allowed_beads`. Project/repository identity syntax and absolute installed executable/database validation follow existing Books constraints; repository must be `Sibiya666/task-tower` for this authorized delivery. `source` is an absolute existing Git checkout. `expected_head` is a full lowercase 40-hex SHA; allowed_beads is a nonempty unique list of valid Beads IDs. Project IDs, resolved database directories and resolved source directories must each be unique (case-insensitively); logical projects may share this one authorized repository. Reject other duplicates, unknown keys, aliases and malformed values. Config size at most 64 KiB; at most 32 projects and 1000 allowed IDs per project. Reject unsafe/private path ancestry using existing path guards, preserving every original predicate and timeout.

Config grants only local readiness observation for the enumerated project/beads. It cannot authorize commands from task text, other repositories, model/account/auth changes or credential scopes. No executable, database, source or config paths leave the host. No source config is installed or live Books settings modified implicitly.

## Fixed bounded host reads

Entry point: `python -m task_tower.beads_admission --config PATH --project ID --bead ID`. Windows only; elsewhere refuse without opening Beads. No auto-discovery of private profiles/databases and no network. Use a single monotonic 30-second operation budget, bounded captured stdout/stderr (8 MiB each command), actual process supervisor EOF/cleanup checks, and no shell. Commands and arguments are constructed by code, never task prose.

Read the configured embedded metadata with the same safe-path/backend/mode restrictions as Books. Strip BD_, BEADS_, DOLT_, GIT_ variables and GH_TOKEN/GITHUB_TOKEN case-insensitively from subprocess environment; set only the selected BEADS_DIR. Run fixed `bd --readonly --sandbox --json ready --limit 1001` and `bd --readonly --sandbox --json show ID`. Reject overflow rather than silently truncating readiness. An injected runner is a unit-test seam, not a configurable production command.

Validate selected task appears exactly once in ready output, show returns exactly that ID, both states are open and unassigned, both issue types are executable task/bug/feature/chore/spike/story (epic/milestone/decision excluded), and shared identity/status/assignee/type fields agree. Official Beads omits assignee for unassigned tasks: normalize absent/null/empty assignee to empty, reject other types or a nonempty value. Explicit id/status/issue_type remain mandatory. Other missing/malformed fields, duplicate IDs, blocked/deferred/closed/claimed tasks and inconsistent reads fail closed. Beads' ready query owns dependency resolution; do not reconstruct a scheduler from prose or dependency exports. Even consistent reads are not a transactional snapshot.

Use bounded fixed local Git reads (each at most 10 seconds and within the common budget) to verify actual HEAD and tree are full SHAs, HEAD equals expected_head, checkout clean including untracked files, and repository metadata belongs to the configured checkout. Source without a valid commit, mismatched pin, dirty state or ambiguous outcome refuses/unknown. Do not mistake cached remote refs for fresh GitHub/main evidence. Recheck HEAD/tree/clean after Beads reads to detect observed mutation; this cannot eliminate a later race.

Git reads must enforce the no-effects promise. Use `--no-optional-locks`, fixed `-c core.fsmonitor=false`, `-c core.untrackedCache=false`, `-c submodule.recurse=false` and disable system/global configuration through process-local environment (Windows NUL global config). Set GIT_NO_LAZY_FETCH=1, GIT_NO_REPLACE_OBJECTS=1 and GIT_TERMINAL_PROMPT=0. Before status/object operations inspect effective local config with fixed bounded `git config --null --list`; discard its private capture after validation and never publish it. Refuse any filter.* definitions, partial-clone/promisor remotes, sparse-checkout, or non-disabled external fsmonitor settings; inspect tracked index entries to refuse gitlinks/submodules. Reject assume-unchanged and skip-worktree index flags before readiness reads: status alone can hide changed tracked content. Require rev-parse --show-toplevel to equal the configured source. Read HEAD/tree locally with replacement objects disabled. Status uses --porcelain=v1 --untracked-files=all --ignore-submodules=all; no diff/textconv/external tools, recursive submodule commands or writable config operations. Tests include malicious filter/fsmonitor and partial-clone fixtures, proving no hook/command/network execution, plus real dirty-file fixtures for both hidden index flags. A configured unsupported checkout gets a fixed refusal code rather than probing until it works.

## Public packet and provenance

Schema version 1, kind `beads.admission.observation`. Identity is `repository:beads:project:bead`, matching Books. Generate fresh UUID run_id and attempt_id on the host for each invocation; these correlate observations only, not stage runs or claims. Include platform windows, outcome, a fixed reason code, source head/tree, policy digest, input digest, observed UTC timestamp and sanitized process facts. Digests use canonical sorted UTF-8 JSON with no NaN; policy digest covers only explicit public project/repository/allowed IDs/expected head/schema, not private paths. Input digest binds identity and normalized selected ready/show facts, not arbitrary task prose.

For each actual subprocess include fixed operation name, pid if actually known, exit code, supervisor status, EOF/cleanup boolean, elapsed numeric duration and captured-byte counts. Never serialize raw argv, cwd, environment, stdout/stderr, exception messages, task body, credentials or paths. Preserve unknown if process completion/cleanup cannot be proven; a JSON response is not process proof. Emit only fixed sanitized errors. Output at most 64 KiB; exit 0 only eligible_observation, 2 known refusal, 3 unknown. No output file argument or filesystem publication side effect.
