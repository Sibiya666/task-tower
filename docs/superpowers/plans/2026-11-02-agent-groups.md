# Agent Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Schedule authorized tasks across explicit project groups with atomic local limits, accepted-result dependencies and durable chat-independent refill.

**Architecture:** Extend the accepted Issue16 pipeline journal, stage worker and watch loop; group policy and DAG analysis are separate pure boundaries. New group-managed runs have independent Git directories; full-ref mutation guards and repository integration fencing remain mandatory.

**Tech Stack:** Python 3.11+, standard library, SQLite, Git, existing Codex/custom harness and GitHub adapters.

**Spec:** `docs/superpowers/specs/2026-11-02-agent-groups-design.md`.

Revision R1 corrects the rejected original base-update binding; retain `docs/tasks/evidence/TT-GROUPS-001/spec-review.md`. This plan is still pending independent specification acceptance and authorizes no implementation.

## Global Constraints

- Python 3.11+ standard library only; Windows, macOS and Linux.
- Default installation capacity is 2 active tasks; configurable range is 1..2 in this release.
- Each group defaults to 1 active task, configurable 1..2 and never above installation capacity.
- One canonical pipeline journal owns execution, group/global capacity, action claims and fair cursors atomically; local SQLite is not distributed ownership.
- No code using unmerged Issue16 runtime contracts before its exact-main CI, independent acceptance and automatic closure; pure policy/DAG modules may precede that gate only after fresh spec acceptance.
- Private policy is authority; Issue/model/card data is untrusted. Keep existing token stripping, pins, checks, path protections, limits, deadlines and independent six-role protocol.
- Preserve all old journal identities/effects/unknowns and committed dispatcher backend mapping. No reset, hidden authority grant or blind effect replay.
- New independent clones retain complete ref mutation checks; legacy linked worktrees retain conservative serialization.
- No merge/close authority added here; #17 remains separate. Completion requires exact-main CI, independent postmerge acceptance and automatic verified Issue closure.
- Original source/admission base/profile/run identities remain immutable. Only private bounded base_update and accepted_main_sources grants permit their respective derived operations; exact accepted-main proof and strict new group protocols are mandatory.

## Review Focus

- Partial native relationships or duplicate task IDs must block only affected graph paths, never silently unblock a parent (Task 2).
- A version1 unknown run without group metadata must still consume global capacity after migration (Tasks 3/4).
- Live role cleanup can finish after worker exit; PID death alone must never free its group/global reservations (Tasks 4/6).
- Independent clones with a shared object alternate or redirected push URL must be rejected even when their checkout paths differ (Task 5).
- A base change while a different group waits for PR acceptance invalidates the old head/base verdict; source unavailability cannot release the barrier (Task 6).
