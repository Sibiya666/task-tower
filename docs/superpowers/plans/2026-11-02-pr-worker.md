# Persistent PR Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a persistent policy-authorized independent PR acceptance/merge worker that holds each repository until verified exact-main postmerge and automatic Issue closure.

**Architecture:** A separate private journal and bounded host controller own review/publication/merge effects. Read-only pipeline or explicitly trusted legacy provenance supplies stage authority through a narrow private postmerge-card adapter; public Markdown and reviewer prose cannot grant it. Integration supports an explicit operator-authorized exclusive main writer boundary plus existing non-bypassed strict server protections; it does not claim atomic expected-base CAS.

**Tech Stack:** Python 3.11+ standard library, SQLite, Git, GitHub REST/GraphQL, existing installed Codex/custom read-only reviewer profiles and process runner.

**Spec:** `docs/superpowers/specs/2026-11-02-pr-worker-design.md`

## Global Constraints

- Python 3.11+ standard library only; Windows, macOS and Linux.
- No installation, model selection, new credential scopes, protection edits, force pushes, manual Issue closure, rollback or background-service installation.
- Issue #16 owns accepted stages and PR creation; #17 neither mutates its journal nor accepts development stages.
- GitHub does not expose atomic expected-base CAS; missing actual operator-authorized exclusive writer boundary or unverified enforced protections blocks merging.
- Every external write has a durable intent; ambiguous effects are never retried merely because time elapsed or the owner restarted.
- Strip GH_TOKEN and GITHUB_TOKEN case-insensitively from every model child. Worktrees are not credential sandboxes.
- Preserve legacy v1 evidence schemes/receipts and genuine GitHubSource/project_worker.verified_done behavior.
- Installed chat-independent real pilot, exact main, independent postmerge and verified automatic closure are mandatory before declaring Issue17 complete.

## Review Focus

- An external main writer advances to an ancestor already contained in reviewed head: strict up-to-date alone must not be advertised as exact-base safety (Tasks 1, 4).
- A same-name success status from another actor or an earlier successful CI attempt hides current failure: require complete current trusted observations (Task 2).
- Public host-looking MD or a copied legacy card is presented without original private process receipts: refuse stage authority and retain old v1 proofs (Task 3).
- Merge response/UUID is lost or expires after a crash: retain barrier without issuing a second PUT (Tasks 1, 4).
- A rerun of the original missing-marker event retains old payload: require provenance-bound follow-up and genuine new event, never manual closure (Task 5).
