# Диагностика старых свидетельств TT-BOOTSTRAP-001

На main 60d78065a524378c920f293c346ef42b1639af87 postmerge-приёмщик обнаружил stale evidence при успешном наборе тестов. Его исходный FAIL-отчёт сохранён без изменений в TT-BOOTSTRAP-001/postmerge-acceptance.md.

Дополнительное сравнение исходного ожидаемого SHA с Git blob и реконструкцией переносов установило полную причину:

- spec: ожидаемый SHA совпадает с Git blob LF; checkout CRLF меняет raw SHA.
- development: ожидаемый SHA точно воспроизводится из того же Git blob с LF на первых 40 переводах и CRLF на последнем.
- test: ожидаемый SHA точно воспроизводится из того же Git blob с LF на первых 51 переводе и CRLF на последнем.

Таким образом, содержательные изменения отчётов для объяснения несовпадения не требуются: нормализация Git устранила смешанные окончания строк. Диагностика была только чтением, без обновления карточки или отчётов задним числом.

Новые приёмки записывают hash_scheme и нормализуют UTF8-текст. Legacy остаётся строгим; существующие записи bootstrap намеренно не мигрированы автоматически. После попадания исправления в main нужна независимая повторная валидация и явное принятие актуальных свидетельств, затем финальная postmerge-приёмка. Задача bootstrap сейчас не считается закрытой.
