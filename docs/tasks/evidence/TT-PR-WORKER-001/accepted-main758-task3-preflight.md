## Actual postmerge/publication API map

`Worker(config,source,reviewer,refresh=None,publisher=None)` retains positional signature. Constructor requires actual Git-root project and creates private `.task-tower/postmerge.sqlite`. Required platforms default all3; max_reviews default1. `_refresh` validates origin and fetches origin main with timeout60. `once()` refreshes/polls, ranks genuine bundles by (run_id,attempt), chooses latest per task, validates cards/ancestry/platforms, claim -> mark reviewing -> detached clean shared clone -> reviewer.review -> save_review -> _apply; then batches publication for every active done row. It must NOT be the PR-controller primitive. Provider must be resolved only after exact current genuine bundle validation, also for later publication paths; bad provider cannot fall back. `_apply` writes local report and calls tasks.accept_task; existing journal rows are keyed only task+commit, so opt-in launch intent must bind/check snapshot, bundle, reviewer identity and request externally before reusing reviewed/done rows.

`ReviewRunner(config).review(checkout,task,bundle,output_dir)` returns BARE `{task_id,commit,verdict,summary,findings}`. It validates pins, uses read-only Codex/custom, strips token env, checks run_command status, validates <=1MiB strict JSON. It does NOT return persisted instance ID, PID/process envelope or host receipt/result digest. Worker._apply writes reviewer label postmerge-agent. Organizational label cannot prove PR-review/postmerge-review distinctness.

`GitHubPublisher(repository,config,token=None,store=None,verify_source=None)`: `receipt(path,bundle,row,required)` returns v1 local-postmerge receipt WITHOUT issue_id until caller fetches immutable Issue; policy contains executor/reviewer labels. `_remote(receipt)` checks task/Issue identity, ancestry and bounded lifecycle comments. `_verify_current_source(receipt)` requires latest genuine source.poll exact bundle. Legacy `publish(path,bundle,row,required,journal)` claims expiring3600s publication ownership and can do POST plus PATCH in one call. Preserve unchanged; new publish_step must never call it or claim_publication.

PRJournal already exposes get/effect/effects/barrier/prepare_publication/begin_effect/observe/record_publication. prepare_publication requires awaiting_closure + live matching repository barrier, immutable issue_id/full receipt. begin_effect comment_post atomically moves prepared -> comment_intent; issue_close moves comment_confirmed -> close_intent. observe confirmed comment requires remote_id/body_sha256/author; close requires issue_id/state/state_reason. record_publication moves acknowledgment phases; published needs full completion_proof. postmerge_review confirmed requires actual result_sha256/receipt_sha256/reviewer_instance_id/process `{pid,exit_code,started,cleanup_confirmed}`. Owner scopes cannot restart/reclaim; old-owner read-only inspection cannot use owner-only state mutations.

`project_worker.verified_done(connection,store,source,issue)` genuinely calls issue_lifecycle and verified_local_receipt. The latter checks trusted publisher/account, immutable Issue ID, v1 publication digest, exact/latest genuine bundle, lifecycle conflicts, main ancestry and all4 evidence schemes (sha256 or sha256-utf8-lf-v1), executor/reviewer label policy. It does NOT itself require issue.state=closed; caller must separately require closed/completed and exact authoritative main. Keep ProjectWorker/v1 shapes unchanged. VerifiedDone must never be replaced by callback True.
