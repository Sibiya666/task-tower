## Concrete typed host context and ownership

Propose new `task_tower/pr_context.py` and `tests/test_pr_context.py`, owned by Task4 for the real reusable read-only construction/validation contract; Task5 owns CLI parsing/lifecycle and invocation. No Task1/2 receipt/schema relaxation and no JSON callable imports.

- `PRPrivateInputs(connections_path:Path,policy_path:Path,journal_path:Path,pipeline_config_path:Path|None)` is a host-only frozen dataclass. executor_config/pipeline_journal/legacy_provenance are read ONLY from the existing strictly validated PR policy. All private paths and SQLite sidecars receive cross-collision/reparse/symlink/hardlink/checkout checks together. A fixed private artifact namespace derived from this PR journal identity is host-created output, not guessed authority discovery; e.g. `<journal filename>.private` beside the private journal, validated against all inputs/checkouts before creation. No new public locator is inferred for an existing policy file.
- `PRHostContext.from_inputs(inputs:PRPrivateInputs)->PRHostContext` loads real connections/executor/PR policies through their actual loaders and retains byte/path fingerprints. It uses pipeline._runtime with the EXPLICIT pipeline path (or a shared read-only extraction of exactly that existing factory, with its own regression tests). Include PR journal/artifact paths in cross-path validation; if a fresh PipelineJournal wrapper is needed, use the same genuine class with all forbidden paths, not a substituted boolean verifier. Never invoke its publisher, stage controller, recover, submit, owner or schema initialization.
- `PRHostContext.current(source:PRSource,task_identity:dict)->FreshEffectContext` reloads and revalidates the actual private inputs on EVERY effect attempt, checks source.policy/connection equal the current authorized policy/connection, obtains source.snapshot from the actual supplied source, derives current criteria using pipeline_policy.criteria_snapshot plus real parse_metadata, and selects the run's actual configured pipeline profile/full pins. It obtains a host-owned immutable authority mirror from exact same-repository head/base objects using existing hardened pr_source Git primitives BEFORE load_stage_authority (prepare_review currently needs authority first). Validate complete commit closure, exact objects/ancestor/path identity, no hooks/global Git config/replace objects and existing byte limits. No dependency on the old mutable executor checkout is introduced.
- The factory creates the real StageAuthorityContext from that live policy/journal/mirror/current criteria and actual profile/pin fingerprints, then calls load_stage_authority. FreshEffectContext contains `{task,snapshot,authority,policy_sha256,private_inputs_sha256}` as host-only values, not public approval flags. Failure, private input drift, source replacement, head/base/criteria/authority/pin/policy mismatch fences the effect. Private-input drift cannot silently substitute a new policy into an already accepted binding: use the existing stale/new-input revision path, with no held barrier or unresolved effect, if re-admission is allowed.
- `PREffects(source,journal,task,owner_id,*,context:PRHostContext)` REPLACES the unbound four-argument constructor for the new Task4 API. The context is mandatory, not an optional fallback or raw authority supplier callback. Before each write and again after durable intent immediately before transport, use current() plus actual journal owner/binding/barrier CAS. A gate failure after committed intent still consumes that intent and cannot authorize a resend. Public data/model results cannot construct a context or force freshness true.

For initial admission, Task5 uses the same context/authority-mirror factory before existing prepare_review; it must not create an original authority dict from task prose or call prepare_review with fake authority just to obtain a mirror. Its later effect objects receive the SAME explicitly configured host context.

## Pending/failure API semantics: reuse actual Task1 guards

Add explicit `PREffects.publish_pending()->dict` and `publish_failure()->dict`; retain publish(receipt), request_merge(receipt), observe_merge, inspect_effect. pending uses a real retained prepared record, exact current authorized input and existing `payload.receipt_sha256=row.input_sha256`; it is NOT a PR review receipt or approval. A failure publishes only a known authorized negative/stale binding: existing row.pr_receipt_sha256 if a matching valid retained receipt exists, otherwise row.input_sha256. Reject unknown/foreign/private-revoked identity rather than publishing diagnostics with guessed authority. A changed/blocked CI or actual reject cannot pass a positive/merge gate; a separately defined negative publication gate may invalidate its exact prior bound head without granting any positive readiness. Merge always requires the FULL fresh approved head/base/authority/CI/findings/writer/protection/server gate. Specify these publication-versus-merge preconditions in the amendment; do not require an approve receipt to emit pending/failure or relax premerge_gate to make those paths work.

Journal shapes and existing pending/success/failure state/owner/hash guards remain untouched. Every call writes at most one status, COMMENT review or merge request. Status target/report identity must bind phase plus exact input/receipt so an older same-head/different-base status cannot reconcile a new intent. Prefer an acknowledged exact owned review URL for final status, or an explicitly specified input/receipt-bearing public target for pending; never rely on generic same-context success alone.
