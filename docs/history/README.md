[Прежняя архитектура](../superpowers/specs/2026-11-01-agent-development-architecture-design.md), [GitHub-конвейер](../shared-conveyor.md), [dispatcher](../dispatcher.md), [pipeline](../pipeline.md) и [группы](../development-process.md) остаются историческими/совместимыми компонентами, а не активным планом нового движка. Не возобновляйте их реализацию только по старому Issue или плану. Сохраняемые исследования и будущие платформенные требования нужно оценивать относительно Beads; закрытие старой реализации не означает готовность ночного или многомашинного режима.

Новая задача считается завершённой после принятого результата в main, требуемого CI и независимой проверки. Слияния проекта сериализуются; PR-приёмка привязана к точным head/base. Разрешения на репозитории, аккаунты и настройки не расширяются сменой движка. Оверлей сам по себе не запускает агентов.

CI для принятого процесса через PR выполняет полный Windows unittest на предполагаемом merge PR, затем один полный прогон точного merge-коммита в postmerge с артефактом события. Повторных прогонов на push ветки и push main нет; новое обновление отменяет только устаревший прогон того же PR. Прямые push в main и merge queue этим маршрутом не покрываются. См. [исследование CI](../research/2026-11-04-windows-ci.md) и [спеку устранения повторов](../superpowers/specs/2026-11-04-ci-trigger-deduplication.md).

Тестовые процессы Windows-шардов используют временный каталог runner с отдельной проверкой настройки. Это уменьшает обходы длинных путей; проверки безопасности, таймауты и весь набор тестов сохраняются. Плавающий отказ проверки отмены остаётся отдельной открытой задачей, а не считается исправленным от зелёного прогона.

Полный набор CLI-тестов распределяется по test ID между четырьмя изолированными Windows jobs. Итоговый check сверяет одинаковую полную инвентаризацию, SHA checkout и непересекающиеся части; ошибка, отмена, пропуск job или неполное покрытие не дают успешного результата. Postmerge публикует `passed` только после всех частей. Обычный последовательный unittest остаётся доступен. Параллелизм сокращает ожидаемое время ожидания, но не гарантирует четырёхкратное ускорение или экономию runner-минут: возможны очередь и неравномерная стоимость тестов. См. [спеку параллельных проверок](../superpowers/specs/2026-11-05-windows-ci-shards.md).

Для чистого текста в `README.md`, `AGENTS.md` и обычных `.md` под `docs/` действует отдельная быстрая проверка: whitespace и новые сломанные локальные Markdown-ссылки, без сети. Сравнивается весь merge с первым родителем, включая удалённые и прежние имена файлов. Код, workflow, шаблоны, symlinks, смешанные или неопределённые изменения получают полный runtime-набор. Для fast path нужны два родителя merge и доступная история; squash/rebase консервативно остаются на полном пути. Stable check явно показывает docs validation, а postmerge публикует только `task-tower-docs-<PR>-windows` с `runtime_tests:not_run`; runtime merge-event при этом не создаётся. Это не полноценный Markdown-renderer и не проверка внешних URL. Подробности и ограничения: [спека docs fast path](../superpowers/specs/2026-11-05-docs-ci-fastpath.md).

Исследование остаточного отказа секундного callback-бюджета ведётся отдельно: один [ограниченный Windows-прогон](https://github.com/Sibiya666/task-tower/actions/runs/41964473875) прошёл за 32,5 секунды и не воспроизвёл задержку. Отдельная оптимизация убирает повторную проверку того же пути перед `_private_stat()`, сохраняя все предикаты и секундный лимит: [второй диагностический прогон](https://github.com/Sibiya666/task-tower/actions/runs/41965554821) подтвердил 54 вызова `lstat` вместо 74 на callback. Общий native-сценарий быстрее не стал; сравнение разных runner не доказывает ускорение задержек. Это не доказательство устранения исторического flake `tt-qrk.4`; [спека диагностики](../superpowers/specs/2026-11-05-hosted-preconnect-diagnostic.md) разделяет принятую оптимизацию и нерешённую причину.

Канонические будущие задачи и зависимости актуализированы в Beads: [карта бэклога](../backlog.md). Прежние GitHub Issues сохранены как внешние ссылки; будущие этапы отложены и не запускаются автоматически. Известная `tt-qrk.4` по решению пользователя не блокирует первый релиз; [условия и read-only наблюдение](../ci-known-issues.md) сохраняют требования к CI и приёмке.

## Разработка

См. [AGENTS.md](../../AGENTS.md), [текущий локальный Beads-источник](../local-beads-books.md) и [устройство оверлея](../../overlay/README.md). Прежняя архитектурная спека сохранена как история; не выдавайте планы оркестрации за реализованные возможности.

Графика создана через imagegen; исходники и промпты находятся в `overlay/assets/`. Эффекты PixelFX имеют MIT license и дополнительные атрибуции в `overlay/vendor/pixelfx/`. Условия WebView2 SDK сохранены в `overlay/vendor/webview2/sdk/`. Лицензия всего проекта отдельно не назначена.

## Архитектурный снимок

Действующее решение пользователя от 2026-11-06 — **Beads + Superpowers + готовый Codex**, см. [текущее направление](../current-direction.md). Beads хранит задачи, Superpowers задаёт метод, существующий Codex исполняет работу. Task Tower связывает их и показывает результат. Прежние Windows-планы и квалификационная цепочка больше не задают следующий этап. Сохраняются независимые проверки и реальные PR/CI/main gates.

| Компонент | Ответственность |
| --- | --- |
| Beads / Dolt | Задачи, эпики, зависимости, захват исполнителем и журнал изменений |
| Superpowers | Обсуждение, спека, план, реализация, тестирование и независимая приёмка |
| Готовый Codex | Исполнение задач существующими поддерживаемыми инструментами и сессиями |
| Task Tower | Оверлей, книжки, отображение исполнителей и необходимая интеграция |
| GitHub | Код, PR, CI и принятый результат в main; прежние Issues сохраняют историю |
| Markdown проекта | Идеи, спеки, исследования, решения и отчёты со ссылками из задач |

Существующий read-only Books-компонент работает **локально с embedded Beads**; его Windows-host описывает поставленную реализацию, а не обязательную платформу выбранного исполнителя. В main добавлен read-only источник книжек: задачи и их хронология, иерархия, зависимости и исполнители. Настройка opt-in; по умолчанию Beads не устанавливается, существующие проекты и настройки не мигрируются. [Подключение локального Beads](../local-beads-books.md).

[Проверка локального запуска Codex](../local-codex-launch-proof.md) фиксирует создание обычной сессии прямым stdio-клиентом в отдельном worktree и успешный read-only ход. Writable-профиль, кнопка запуска и Beads-интеграция этим опытом не поставлены.

Это ещё не постоянный пул агентов: адаптер книжек не запускает модели, не выполняет автоматический merge и не закрывает задачи. Настоящие процессы, CI и приёмка проверяются отдельно; `closed` в источнике не является доказательством принятого кода. Embedded-режим допускает одного писателя за раз. VPS, HTTP/server, несколько машин и Linux/macOS — отдельные будущие этапы, без текущего развёртывания.

Исторические активации и карточки сохранены в [backlog](../backlog.md), без автоматического возобновления старых планов. Перед выполнением выбранной задачи нужны её фактическая готовность, native atomic claim и readback владельца. [Admission](../beads-admission.md) остаётся read-only наблюдением и не заменяет эти действия.

## CLI готовности

CLI аудита готовности сохранён как отдельный инструмент; он не становится исполнителем задач Beads. Историческая обработка GitHub merge-событий описана в [postmerge worker](../postmerge-worker.md).

```powershell
python -m task_tower audit --project C:/path/to/project --manifest examples/dialoid.project.json --output ../runtime/readiness.json
```

Без `--run-checks` выполняется аудит; с ним — явно запрошенные команды манифеста с ограничением времени и жизненного цикла процессов. Это не sandbox и не разрешение на автономное слияние. Коды выхода и ограничения: [документация CLI](../readiness.md).

## Проверки

```powershell
python -m unittest discover -s tests -v
Push-Location overlay
python -m unittest -v
node --test test-books-policy.cjs test-books-host.cjs test-books-browser.cjs test-web.cjs test-room-skins.cjs test-presence.cjs test-presence-browser.cjs test-scene-position.cjs test-session-light.cjs test-tower-arrivals.cjs test-world-policy.cjs test-world-browser.cjs test-visual-audit.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File overlay.ps1 -SmokeTest
Pop-Location
```

Браузерным тестам нужны Playwright, Sharp и установленный Edge. Пути к bundled Node-модулям Codex сейчас машинно-зависимы. Нативный smoke проверяет host и включает детерминированные Books-фикстуры; живой источник данных проверяется отдельно. Он сохраняет PNG в игнорируемую `overlay/runtime/` и закрывает тестовое окно; синтетический ввод не заменяет проверку настоящей клавиатуры.

## Headless Linux orchestrator

The explicit [Docker/host-connector procedure](../runtime/headless-operation.md#linux-docker-deployment-stage-6)
keeps Beads and runtime journals in separate persistent volumes and Codex/repositories
on the host. It includes a disposable native Linux smoke; fixture/container success
alone does not establish acceptance of the real autonomous pilot. No canonical
backlog is migrated and no unattended service is installed by default.
