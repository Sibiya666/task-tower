# Действующее направление Task Tower

**Решение пользователя от 2026-11-06:** «Убери старые Windows-планы из действующих инструкций и навыка, чтобы они больше не всплывали. Оставь только Beads + Superpowers + готовый Codex».

Этот документ и актуальный `AGENTS.md` заменяют прежнюю маршрутизацию к Windows-квалификации, плану B и цепочке B → C. Датированная единая спецификация 2026-11-05, Windows-планы, исследования и handoff сохраняют историю; их прежние утверждения о «текущей authority» больше не действуют. Читать их нужно только для явно запрошенной исторической справки или конкретного технического факта, не для выбора следующего этапа.

## Состав

| Компонент | Назначение |
| --- | --- |
| Beads / Dolt | Единственная очередь задач, зависимости, владельцы и история |
| Superpowers | Метод разработки: обсуждение, спецификация и план по необходимости, реализация, тесты и независимая проверка |
| Готовый Codex | Существующий исполнитель и его поддерживаемые инструменты, сессии и плагины |
| Task Tower | Связь этих компонентов, Books и overlay |
| GitHub | Исходники, PR, CI и принятая версия main |

Использовать существующие возможности. Дописывать только конкретно недостающую связь, если её необходимость подтверждена задачей. Не создавать второй task engine, постоянный граф ролей или замену Codex. Количество агентов определяется задачей; разработчик не принимает собственный результат.

## Обычная работа

1. Прочитать актуальную разрешённую задачу Beads, её зависимости и владельца. Перед выполнением получить native atomic claim и проверить владельца чтением обратно. Сохранённый пакет, старый план или display-конфиг не заменяет владение.
2. Применить Superpowers в объёме задачи. Сохранить чужой WIP; работать в отдельной ветке/worktree. Использовать готовый Codex в существующих разрешениях, без самовольной смены модели, аккаунта, авторизации или установки инструментов.
3. Получить фактический результат и уместные проверки. Независимый reviewer читает исходную задачу и весь результат в отдельном контексте; исправивший материал reviewer становится его автором.
4. Для поставки в репозиторий сохранить свежую независимую whole-PR приёмку точных head/base, настоящий `task-tower/pr-acceptance`, весь применимый CI, защиту main и merge по expected head. Затем проверить exact-main CI и независимую postmerge-приёмку. Только после этого закрыть каноническую задачу и прочитать её историю обратно; результат интеграции с Books проверяется по настоящему API/data/source output в рамках текущей границы приёмки ниже.

Отдельная Windows-квалификация, G1/G2, ACL-эксперименты и план B **не являются предварительными условиями этого маршрута**. Не возобновлять их автоматически при запросе исполнить задачу или связать компоненты. Конкретный отказ существующего инструмента разбирается в рамках конкретного действия; он не запускает заново старую программу квалификации.

## Текущая граница приёмки

**Прямое решение пользователя от 2026-11-06 для последующих задач:** убрать UI из приёмки; пользователь исправит его отдельно и затем вернёт в приёмку. До отдельного прямого указания о возврате UI/visual/manual/native-window/screenshot/actual Books UI observation отложены и не являются gate. Не планировать и не запускать UI diagnostics или визуальную приёмку только ради закрытия задачи.

Принимать конкретный результат API/data/source integration, контрактные и security-проверки, настоящий output и независимые PR/main receipts. Реальный источник Books можно проверить штатным read-only API/data producer без окна. Обязательное ранее наблюдение native `overlay.ps1 -SmokeTest` после host/launch/render изменений также временно отложено и не блокирует закрытие.

Это не отменяет существующий CI, применимые автоматические тесты (в том числе с visual/native в названии), проверки native data boundary, security assertions или независимые exact-H/B и exact-main gates. Failed/skipped checks не становятся pass. Не заявлять, что UI проверен, принят или исправлен; прежние неуспешные наблюдения, планы и receipts сохраняют фактический исход и историю. Автоматически возвращать UI gate по старому плану, зелёному CI или закрытому source state нельзя — нужно новое прямое решение пользователя.

## Сохраняемые границы

- Существующие проверки безопасности, приватности и CI сохраняются. Названия платформ в командах overlay, checks и артефактах описывают уже имеющуюся реализацию, а не обязательную платформу исполнителя или новый план работ. Этот документ не меняет платформы продукта/CI.
- Не читать реальные секреты для диагностики; не передавать приватные конфиги, DB paths или credentials агентам. Сохранить установленные границы доверенных host helpers и удаление GitHub-токенов из модельных дочерних процессов.
- Не повторять внешний эффект с неизвестным исходом. Сверить фактический результат или сохранить unknown/fence. Завершение процесса, `closed` и ответ модели не заменяют независимую приёмку.
- Не активировать старый конвейер, workers или мониторы; не создавать их дубликаты. Установка навыка/плагина сама по себе не доказывает поставленную автономную службу.
- Эта правка меняет инструкции. Она не переносит claims, не закрывает карточки, не меняет зависимости в Beads и не принимает исторические PR. Для выбранной текущей задачи проверять фактический канонический статус; архивные карточки не становятся обязательной очередью для всей разработки.

История задач сохранена в [backlog](backlog.md). Технические границы уже принятого read-only компонента описаны в [admission](beads-admission.md); это описание компонента, а не предварительная Windows-программа для любого использования Codex.
